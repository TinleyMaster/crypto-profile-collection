# 参考锚点（现场生成，勿当常量）

> ⚠️ **本文件记录的是「解读范式」与「分布形状」，不是某个币的当前数值。**
> `biz.asset_price_elasticity` / `asset_unlock_reaction` / `asset_flow_factor` 三表**每日 21:40–22:10 滚动重算**，
> 同一币的 `ar_72h_mean`、`excess7_mean`、n 值每天都会变。
>
> **引用前必须现场生成**：
> ```bash

> 一天后 AAVE 的 `rs_90d` 就从 +48.2 掉到 +30.0、`ar_72h_mean` 从 +4.68 变成 +3.84。

## 一、价格弹性

### 分布形状（该看懂什么）

| 评级 | 资产数 |
|---|---:|
| 样本不足 | 198 |
| 中高弹性 | 42 |
| 低弹性 | 42 |
| 高弹性 | 32 |
| 负弹性 | 29 |

**读法**：全库 343 个可评级资产里，「样本不足」占 58%。这意味着**多数币根本不足以断定催化剂有效性**。
遇到样本不足别硬套范式，如实写「样本不足，不外推」。

### 解读范式（这才是锚点的价值）

| 类型 | 特征 | 该怎么用 |
|---|---|---|
| **有 beta 无 alpha** | RS/beta 高（跟得动大盘），但 AR72 低、命中率 ≤50% 甚至显著低于抛硬币 | **不得按"催化剂驱动"给溢价**。上涨本质是行情 beta |
| **真事件驱动** | AR72 显著为正 + 命中率 z 值显著 >50% | 可按事件定价，催化剂有超额价值 |
| **反向** | AR72 显著为负 | 利好即出货，催化剂反而是减仓信号 |

典型归属（**仅示意类型，数值已过期，勿引用**）：LINK / UNI 属「有 beta 无 alpha」；AAVE / ONDO 属真事件驱动。

### 判读必做
1. **分事件类型**（`by_event_type`）：哪类消息有效、哪类无效。某币可能 `listing` 有效但 `partnership` 无效。
2. **分影响强度**（`by_impact`）：只有 weak 档有效 → 确定性来自炒作而非基本面 alpha，必须标注。
3. **看中位数**：`ar_72h_median` 抗离群，与均值差异大说明分布偏斜，优先信 median。

### 红线
- 事件源是新闻流 + 交易所公告，**非项目基本面催化**，含同名/批次归因噪音
- 样本期随库滚动（约 2.5 个月），**弹性能否外推需谨慎**
- **BTC 自身 AR72 恒 ≈0、hit 恒 0** 是基准所致，**不代表"BTC 无弹性"**
- 同币事件窗口常重叠（间隔 <72h），二项检验独立性不成立 → **z 值系统性偏高**，`|z|≥1.96` 要打折看

## 二、解锁表现

### 分布形状

| 评级 | 资产数 |
|---|---:|
| 无数据 | 278 |
| 样本不足 | 223 |
| 中性 | 20 |
| 偏抗解禁 | 16 |
| 抗解禁型 | 4 |
| 偏解禁即崩 | 3 |
| 解禁即崩 | 3 |

**读法**：能给出明确评级（非无数据/样本不足）的只有 **46 个资产**。解锁事件天然稀少（多数币 3–7 次），
`n<8` 时统计推断力弱，评级仅供参考。

### 全样本基线
解锁整体**不压垮价格**（历史全样本 fwd7 超额 +0.69%~+1.7%，上涨率 ~48%）。
所以「有解锁」≠「会跌」。必须看**该币自己的** `excess7_mean`。

### 解读范式

| 类型 | 含义 | 该怎么用 |
|---|---|---|
| **抗解禁型**（excess7 ≥ +5） | 解锁反涨 | 解锁可能是**买点**，不得按"解锁=利空"定调 |
| **解禁即崩型**（excess7 ≤ −5） | 解锁后显著下跌 | 真实风险，须给**下一个解锁日 + 规避窗口** |
| 中性 | 无明显方向 | 按前瞻压力判断 |

### 受益人类别：三层口径（详见主文件 P1.7）

**核心经验（2026-10-16 全量实测，仍成立）**：团队主导的币解锁后 7 天超额 **−2.78%、崩率 32%**，
显著差于社区/生态主导（+2.6% / +3.2%）。→ `dominant_beneficiary=team` 必须提示内部抛压。

三层常打架，**以事件级为准，冲突并列标注**：
- 事件级 `tokenomics_hero`：仅覆盖下一期，最精确
- 事件级 `cmc_next`：覆盖 747 资产，额外给美元金额 + 占流通比
- 资产级 `dominant_bucket`：整条生命周期口径，仅背景

### 红线
- 源为聚合站（tokenomics.com / tokenomist.ai），非一手官方
- **CMC 有荒谬解锁日脏值**（实测 JUP=2123-01-01、P2PS=2035-12-25）。`ingest_cmc_unlocks.py` 已把「> today+5 年」整条置 NULL
  → 查库用 `dominant_bucket IS NOT NULL AND next_unlock_date IS NOT NULL` 过滤；**报告绝不引用 >5 年的解锁日**
- **CMC 是补充不是替代**：历史纵深（2016→2030 / 3800 事件 / 614 资产）仍以 `asset_unlock_event` 为准

## 三、资金流因子

### 分布形状

| 评级 | 资产数 |
|---|---:|
| 资金流入 | 365 |
| 中性 | 344 |
| 资金流出 | 197 |

**读法**：分布略偏流入（可能反映样本期行情），**不要因为有 365 个"资金流入"就认为都能买**——
这是全市场横截面，不是相对强度。

### 双确认范式（弹性 × 资金流）

| 组合 | 判定 | 置信 |
|---|---|---|
| 高弹性 + 资金流入 | ★双确认：消息值钱且资金真进 | 最高 |
| 高弹性 + 资金流出 | ⚠背离：消息强但资金撤 | 谨防利好出尽，不给高置信 |
| 低弹性 + 资金流入 | 资金进但消息不涨 | 可能是 beta 或吸筹，需额外证据 |
| 低弹性 + 资金流出 | 双弱 | 规避 |

### 三源与断更

| 源 | 表 | 阈值 |
|---|---|---|
| OBI 盘口失衡 | `biz.orderbook_depth_history` | 24h |
| OFI 主动成交失衡 | `biz.cg_taker_volume_hist` | 24h |
| 链上净流 | `biz.onchain_netflow_hourly` | 48h |

**v2 起断更源自动剔除出评分**并渲染告警。看到「⚠️ 数据断更告警」时：
1. 剩余源权重实际被放大 → **置信度必须下调**
2. 补数据：`python bin/ingest_cg_taker.py --stale`
3. 重跑因子

> 历史教训：OFI 曾断更 15 天（2026-10-07 → 10-22）而因子照常输出「中性」——
> 因为当时口径是"各源以自身最新时点为锚"，等于用两周前数据冒充今天。UNI 剔除 OFI 后评级从
> 中性 52.6 翻成资金流入 62.76。**这就是为什么必须看告警。**

### 红线
- 盘口/主动成交反映**当下**资金压力，非长期趋势
- 三源覆盖不全时如实标「无数据」，不得据单一源下强结论

## 四、催化剂影响分级

`biz.catalyst_impact` 覆盖率 **99.4%**（`unknown` 仅 0.6%）：
- **strong**：主网上线、协议升级、大所上新、大额机构融资、关键法案、代币机制变更
- **medium**：重要合作、grant、跨链集成
- **weak**：普通推文、AMA、社区活动、次要合作

**判读**：strong/medium 档 AR72 明显高于 weak → 基本面事件驱动；**只有 weak 有效 → 炒作驱动**，须明确标注。
某币 `unknown` 反而占多数 → 事件源特殊，标注并降权，但**不得据此否定其事件驱动属性**。

## 五、如何现场重算锚点

```sql
-- 弹性分布
SELECT elasticity_grade, count(*) FROM biz.asset_price_elasticity
WHERE as_of = (SELECT max(as_of) FROM biz.asset_price_elasticity)
GROUP BY 1 ORDER BY 2 DESC;

-- 解锁分布
SELECT reaction_grade, count(*) FROM biz.asset_unlock_reaction
WHERE as_of = (SELECT max(as_of) FROM biz.asset_unlock_reaction)
GROUP BY 1 ORDER BY 2 DESC;

-- 资金流分布
SELECT flow_grade, count(*) FROM biz.asset_flow_factor
WHERE as_of = (SELECT max(as_of) FROM biz.asset_flow_factor)
GROUP BY 1 ORDER BY 2 DESC;
```

单币数值一律走脚本 `--md`，不要从本文件抄。
