## 1. 背景与问题

### 1.1 现状

催化剂评分管道（G1→G6）当前存在一个根本性缺陷：**评分标准的权重全部是先验拍脑袋值，从未被历史价格影响验证过**。

| 权重 | 当前来源 | 问题 |
|------|----------|------|
| `event_type_weights`（listing=95, burn=80...） | 人工设定 | 未经实测，可能高估/低估某类事件 |
| `authority_scores`（binance_listing=100...） | 人工设定 | 未经实测，来源权威度≠实际影响 |
| `scope_score_rules`（单币90>板块60>全市场30） | 人工设定 | 未经实测，聚焦度与影响的真实关系未知 |
| `resonance_weights`（excess 0.5/vol 0.3/dir 0.2） | 人工设定 | 未经实测，哪个维度预测力强未知 |
| `composite_score_weights`（kind 0.25/res 0.30...） | 人工设定 | 未经实测，各维度对最终收益的贡献未验证 |

### 1.2 核心问题

- 一个"评分 80 分 A 级"的信号，历史真实命中率是多少？——**不知道**
- "listing"事件到底比"tech_upgrade"强多少？——**是猜的**
- 币安官方源的信号真的比 KOL 源强吗？——**是猜的**
- resonance（共振）高的信号后续表现真的更好吗？——**未验证**

### 1.3 目标

建立「催化剂 → 实际价格影响」的**后验验证闭环**：

```
催化剂发布 → 规则评分(先验) ──→ 生成信号/邮件/AI评审
     │                                  │
     ▼                                  ▼
长周期行情追踪(实测) ←────── 价格结局 ←── 用户按信号操作
     │
     ▼
统计校准(命中率/超额收益/IC) ──→ 校准权重 ──→ 下一轮评分用校准权重
```

**一句话**：让评分的每个权重都变成「实测出来的」，而不是「拍脑袋定的」。样本不足时用先验兜底，样本足够时用实测。

## 4. 详细设计

### 4.1 表 1：`catalyst_outcome` 催化剂价格结局

```sql
CREATE TABLE IF NOT EXISTS biz.catalyst_outcome (
    outcome_id      BIGSERIAL PRIMARY KEY,
    catalyst_id     BIGINT NOT NULL REFERENCES biz.asset_catalyst(catalyst_id) ON DELETE CASCADE,
    asset_id        BIGINT NOT NULL REFERENCES core.asset(asset_id) ON DELETE CASCADE,

    -- 基线时点（信号生成时刻 = 交易决策起点）
    signal_id       BIGINT REFERENCES biz.catalyst_signal(signal_id),
    base_time       TIMESTAMPTZ NOT NULL,     -- = catalyst_signal.created_at
    base_price_usd  NUMERIC(20,10),           -- 基线价（发布后第一个可得 K 线收盘）

    -- 各窗口绝对收益（%）：L1 用 K 线精确，L2 无小时级数据记 NULL
    ret_4h          NUMERIC(10,4),            -- L1: 4h K线 / L2: NULL
    ret_24h         NUMERIC(10,4),            -- L1: 24h K线 / L2: CMC近似
    ret_72h         NUMERIC(10,4),            -- L1: 72h K线 / L2: NULL
    ret_7d          NUMERIC(10,4),            -- market_daily
    ret_14d         NUMERIC(10,4),            -- market_daily

    -- 各窗口超额收益（扣 BTC beta，%）：同源计算
    excess_4h       NUMERIC(10,4),
    excess_24h      NUMERIC(10,4),
    excess_72h      NUMERIC(10,4),
    excess_7d       NUMERIC(10,4),
    excess_14d      NUMERIC(10,4),

    -- 命中判定（相对 impact_direction，缺失时用 event_type 默认方向）
    hit_4h          BOOLEAN,
    hit_24h         BOOLEAN,
    hit_72h         BOOLEAN,
    hit_7d          BOOLEAN,

    -- 量能验证
    vol_ratio_24h   NUMERIC(10,4),            -- 24h量 / 7日均量
    vol_ratio_72h   NUMERIC(10,4),

    -- 极端风险
    max_drawdown_24h NUMERIC(10,4),           -- 24h内最大回撤（%）
    max_gain_24h    NUMERIC(10,4),            -- 24h内最大涨幅（%）

    -- 元信息
    impact_direction TEXT,                    -- 冗余快照：bullish/bearish/neutral（可空）
    direction_src   TEXT,                     -- impact 表 | event_type默认 | null
    data_tier       TEXT NOT NULL DEFAULT 'L2',  -- L1(有K线) | L2(无K线)
    outcome_state   TEXT NOT NULL DEFAULT 'pending',
                    -- pending(未到最终窗口) / resolved(已结算) / no_data(无行情)
    last_window     SMALLINT DEFAULT 4,       -- 已结算的最大窗口小时数（4/24/72/168/336）
    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    UNIQUE (catalyst_id, asset_id)
);

CREATE INDEX IF NOT EXISTS idx_catalyst_outcome_cat
    ON biz.catalyst_outcome (catalyst_id);
CREATE INDEX IF NOT EXISTS idx_catalyst_outcome_asset
    ON biz.catalyst_outcome (asset_id, outcome_state);
```

**窗口结算规则**（v1.1 修正）：
- 4h / 72h：仅 L1（有K线）计算，L2 记 NULL
- 24h：L1 用 K 线，L2 用 `cmc_asset_quote_snapshot` 的 percent_change_24h（近似，标注 source）
- 7d / 14d：全部用 `asset_market_daily`（日频，复用 KOL 回测的 `get_price_series`）
- 每条记录按 `last_window` 递增更新，直到 336h（14d）结算 → `resolved`

### 4.2 表 2：`catalyst_calibration` 校准权重

```sql
CREATE TABLE IF NOT EXISTS biz.catalyst_calibration (
    calib_id        BIGSERIAL PRIMARY KEY,
    dim             TEXT NOT NULL,   -- event_type | source | scope | resonance_band
    dim_value       TEXT NOT NULL,   -- listing / binance_listing / single_pair / 80-100

    sample_count    INT NOT NULL DEFAULT 0,
    hit_rate        NUMERIC(6,4),    -- 方向命中率（bullish→涨，bearish→跌）
    avg_excess_24h  NUMERIC(10,4),   -- 24h平均超额收益
    avg_excess_72h  NUMERIC(10,4),
    median_excess_72h NUMERIC(10,4),
    win_rate_72h    NUMERIC(6,4),    -- 72h 方向正确率
    ic_24h          NUMERIC(8,4),    -- 信息系数：评分与24h超额的相关
    calibrated_score SMALLINT,       -- 校准后权重 0-100
    prior_score     SMALLINT,        -- 原先验权重（对比用）
    weight_mode     TEXT NOT NULL DEFAULT 'prior',  -- prior(样本<30) / calibrated
    window_start    DATE NOT NULL,   -- 校准窗口起点
    window_end      DATE NOT NULL,   -- 校准窗口终点
    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    UNIQUE (dim, dim_value, window_end)
);

CREATE INDEX IF NOT EXISTS idx_catalyst_calib_dim
    ON biz.catalyst_calibration (dim, dim_value, window_end DESC);
```

**校准口径**：
- 样本 < 30 → `weight_mode='prior'`，继续用先验
- 样本 ≥ 30 → `calibrated_score` 由 hit_rate + avg_excess 综合得出，`weight_mode='calibrated'`
- ⚠️ 仅对 **L1（有K线）且资产匹配确认** 的样本参与校准（防止 ARC 类 ticker 同名污染）

### 4.4 脚本 1：`collect_catalyst_outcome.py`

- 调度：每日增量（cron 或 daemon 内挂）
- 逻辑：
  1. 取 `catalyst_signal` 中未 `resolved` 的 `(catalyst_id, asset_id)`，join `asset_catalyst` 拿事件类型
  2. 判定 data_tier：查 `asset_klines` 是否有该资产 1h 数据 → L1 / L2
  3. 按 `last_window` 计算未结算窗口（L1: 4h→24h→72h；全部: 7d→14d）
  4. 命中判定：优先 `catalyst_impact.impact_direction`，缺失用 event_type 默认方向（listing→bullish 等），仍无则 `direction_src='null'`
  5. 更新 `last_window`，336h 结算后置 `resolved`
- 幂等：已结算窗口不重复计算
- 数据源：K线 `asset_klines`、日频 `asset_market_daily`、兜底 CMC 快照

> ⚠️ **结算口径修正（v1.2，2026-09-18）**：本表存在**两套 `base_time` 口径**，取样时不可混用：
> - **前向追踪（collect）**：`base_time = catalyst_signal.created_at`（信号生成时刻 = 真实交易决策起点）
> - **历史回放（backtest）**：`base_time = asset_catalyst.published_at`（催化剂发布时刻，用于长历史回填）
>
> 另外 `backtest_catalyst_impact.py` 原先**没有 now 闸门**：窗口未到期时 `kline_close_at`
> 会取到 K 线末尾，把「base 到最新一根」冒充 72h 收益。实测伪造 60 行
> （`ret_4h = ret_24h = ret_72h` 或 0.0000）。已修：只回放 `published_at + 14d <= now`
> 的历史催化剂，并按窗口逐个判到期清理存量未到期列（清理 189 行）。
> **做校准/评估取样时**：必须加 `base_time + INTERVAL '72 hours' <= updated_at` 之类
> 的到期闸门，否则未到期行会被当成已结算样本污染 hit_rate。

### 4.5 脚本 2：`calibrate_catalyst_weights.py`

- 调度：每周一次
- 逻辑：
  1. 从 `catalyst_outcome`（仅 `outcome_state='resolved'` 且 `data_tier='L1'`）聚合各维度
  2. 资产匹配过滤：A级用 `ai_deep_review.asset_match_confidence`，B/C级用 link 匹配状态兜底（见 §8 风险 5）
  3. 计算 hit_rate、avg_excess、win_rate
  4. 生成 `calibrated_score`（样本≥30）
  5. 写入 `catalyst_calibration` + `calibration_log`
  6. 输出校准报告（CSV / 控制台）

## 5. 校准分计算公式

### 5.1 命中率

```
hit_rate = (# 超额收益方向 == impact_direction) / total_samples
```

- bullish 事件：excess > 0 记命中；bearish：excess < 0 记命中
- 中性事件（neutral）不参与命中率（方向无意义），只看绝对波动
- `direction_src='null'`（方向未知）的样本不计入命中率分母

### 5.2 校准权重

```
calibrated_score = 50
                + hit_rate_delta * 60        # 命中率每高出基准(50%) 10pct → +6分
                + excess_score * 40          # 平均超额收益贡献（72h窗口，饱和在±10%）
                - volatility_penalty         # 高波动事件扣分（最大回撤>15% 扣5）
```

**设计意图**：校准分 0-100 与先验分同量纲，可直接替换。

### 5.3 样本门槛与融合

- 样本 < 10：`weight_mode='prior'`（先验）
- 10 ≤ 样本 < 30：`weight_mode='prior'`，但记录 trend（趋势观察）
- 样本 ≥ 30：`weight_mode='calibrated'`（实测权重生效）

## 8. 风险与注意

| 风险 | 说明 | 对策 |
|------|------|------|
| 1. 小样本噪声 | 某 event_type 只有 5 条样本 | 样本<30 一律用先验，绝不硬切 |
| 2. 事件-价格因果混淆 | 涨了不一定是催化剂作用 | 用超额收益扣 BTC beta + peer 中位数对照 |
| 3. 价格异动数据污染 | 已发现历史有价格尖峰 | 复用 `is_anomaly` 标记过滤（market_daily 已有） |
| 4. K线覆盖盲区 | 仅 27.5% 资产有 K线 | 分层 L1/L2：L1 精确、L2 只用 24h 近似+日频，小时级记 NULL 不硬凑 |
| 5. 资产不匹配 | ticker 同名不同币（ARC 案例） | A级过滤 `asset_match_confidence`；B/C级无 AI 评审 → 用 `asset_name` 与 catalyst 标题 token 交集校验，交集为空的标 `match_suspect` 不参与校准 |
| 6. 过拟合 | 校准分太贴合历史 | 每期滚动窗口（近 90 天），不用全量 |
| 7. 权重震荡 | 校准分每周跳变 | 变更限幅：单周校准分变化 ≤ ±15 |

## 11. 实测校准的落地修订（d1-d5，2026-09-18）

> 本节记录「用 outcome 实测反对先验」后对规则与链路的实际改造，每项附实测依据。
> 两条原则不变：
> ① `composite_score` 是 tier 的唯一来源（口径单点真源，下游只读不算）；
> ② `catalyst_rules.yaml` 先验值只作兜底，实测结论仅在样本充分时覆盖先验。

### d1 G1 新增「发布前启动程度」惩罚项（追高扣分）

- 问题：原 G1 只衡量事件强度（event_type / authority / scope），不衡量
  「价格是否在催化剂发布前已经跑完」，因此对追高型催化剂的评分偏高。
- 改造：G1 分级增加**发布前启动程度**因子——发布前涨幅越接近/超过阈值，
  base_strength 扣分越多（迁移 `fix_050_catalyst_grade_prelaunch.sql`）。
- 方向：与 d3 一致——「已经动过的价格」不再给满分。

### d2 权重校准解耦「强度」与「方向可靠性」

- 问题：校准分把 `hit_rate`（方向可靠性）与 `avg_excess`（幅度强度）揉成一个分数，
  导致「幅度大但方向接近随机」的维度被高估。
- 改造：`calibrate_catalyst_weights.py` 分列计算方向项与强度项再合成 calibrated_score；
  样本门槛不变（<30 走先验，10-30 记录趋势）。
- 影响：校准分不再由单一大波动样本拉高，方向可靠性成为独立约束。

### d3 信号分层：价格定价程度决定可动作性（关键口径反转）

| resonance_state | 含义 | status | 推送 |
|---|---|---|---|
| confirmed | 价格已同向反应 ≥5% 且放量 | `watch` | 否（观察池） |
| weak | 价格温和 / 未充分反应 | `open` | 是（可动作） |
| divergent | 价格方向与催化剂背离 | `invalid` | 否（剔除） |
| pending | 未反应 | `watch` | 否（观察） |

- 实测依据（`biz.catalyst_outcome`，**仅前向样本** `ret_source='klines+market_daily'`，
  收益自信号生成时刻起算）：

| resonance_state | 72h 超额 | 样本 | 方向命中 |
|---|---|---|---|
| confirmed | **-2.17%** | 49 | 40.9% |
| weak | **+0.64%** | 481 | 59.3% |

  → 「等价格确认（confirmed）再开单」等于**追高**，前瞻期望为负；只有价格
  尚未充分反应（weak）时开单才有正期望。
- 状态迁移：`expired/done` 为终态冻结；其余行每轮跟随当前 resonance_state 重算
  （watch→open 晋升 = 价格行为确认；open→watch 回退 = 已定价不再可动作）。
- 存量收敛：迁移 `fix_053_catalyst_signal_watchlist.sql`（status 枚举加 `watch`
  + 观察池索引），存量行按新口径全量收敛。
- **强制约束**：任何写 `status` 的路径都必须经
  `CatalystSignalBuilder._initial_status()` 的映射（含慢通道 G3-G5 重算，
  **不得硬编码 `'open'`**），否则已定价/未反应的信号会被误放进可动作集合。
- 线上只读校验（全表）：`open` 全为 weak、`invalid` 全为 divergent、
  `watch ⊆ {confirmed, pending}`、终态未被改写——四项越界均为 0。

### d4 event_type 方向映射实测校正

- `tech_upgrade` 实测呈「利好出尽」→ 默认方向由 bullish 改 **bearish**；
- `funding` / `burn` 样本不足 → 方向降为 **neutral**（不参与命中率分母，
  也避免污染二阶/共振的方向一致性判断）；
- 迁移 `fix_051_catalyst_direction_calibration.sql`，供 outcome 命中判定复用。

### d5 二阶信号共振刷新（本轮新增，设计变更）

- 问题：二阶（sector 传导）信号共振**只在创建时算一次**。
  `run_slow_second_order()` 候选集是 one-shot（`NOT EXISTS biz.catalyst_second_order`）
  + 写入用 `ON CONFLICT DO NOTHING`，而 resonance 在 composite 中权重 **0.30（最大项）**
  ——导致二阶信号评分长期冻结在创建时点。
  实测：3,670 条二阶信号中 **2,352 条** `resonance_score` 与当前 peer-median 期望值
  不符，其中 **521 条**连 `resonance_state` 都已失真。
- 改造：慢通道新增独立步骤 **二阶共振刷新** `refresh_second_order_resonance()`，
  执行顺序：二阶受益展开 → G3-G5 补全 → **二阶共振刷新** → 过期巡检。
  每轮对「已有二阶映射且未终态（open/watch/invalid）」的信号重算：

```
peer_median     = 该 catalyst 直连资产 resonance_score 升序取 len//2
resonance_score = max(0, int(peer_median * 0.7))
resonance_state = confirmed(>=70) / weak(>=35) / pending
composite/tier  = G6 公式（CatalystSignalBuilder，单点真源）
status          = d3 动作闸门（tier=None → invalid）
```

- **不覆盖**字段：`entry_price/stop_loss/take_profit/rr_ratio`（G5 战术位）、
  `persistence/fundamental_detail/technical_state`（G3-G4）、
  `ai_reason/investment_cycle`（G7）、`expires_at`（过期语义）。
- 缺数据不反向降级：无 peer 共振行的 catalyst 跳过并单独计数
  （当前 18 行 / 19 个 catalyst），不把「缺失」当「0 分」处理。
- 降噪与幂等：值无变化的行**不写**（`updated_at` 被「信号滞后」口径引用，
  避免无谓抖动）；锁冲突按 `_LockRetryExhausted` 跳过，下轮重算；
  终态行冻结；temp 表 `ON COMMIT DROP` 保证重试可重建。
- 收敛方式：**无需批量迁移**——存量行在下一轮慢通道自动收敛（幂等）。
  事务内回滚单测：扫描 1,491 行 / 回写 105 行 / 转 open 26 / 退出 open 39 /
  无 peer 跳过 18；受保护字段零改动；四项不变量仍为 0。
- 边界：二阶信号 tier 上限仍为 C，其晋升 open 只进 trace 与早报观察区
  （不占 A 级 Alert 邮件位）。
