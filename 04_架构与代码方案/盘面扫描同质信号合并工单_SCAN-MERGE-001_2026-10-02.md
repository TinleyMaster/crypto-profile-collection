# 工单 SCAN-MERGE-001：告警邮件同质信号合并（BRK 同根破位 → 市场级事件卡）

> 状态：**已闭环**（2026-10-02，三通道全过）
> 类型：**线上渲染层行为变更**（只改邮件正文，零 DB 变更）
> 定位来源：设计方案 §8.1.10 缺陷③ / 行动项③「同 bar 多币同根破位的同质信号合并可单列」；
> 用户 2026-10-02 确认「先做同质信号合并」（盘面告警线回归「状态感知」定位后的第一项工程改进）。

## 1. 结论先行（本工单要回答什么）

**问题**：一次市场级事件被渲染成 N 张各自看似独立的卡片。实物：2026-09-23T14 一根 1h K 线
**92 个 BRK 币同时向下破位**（占全量告警的 20%），邮件里 92 张卡片每张都渲染
「共振 / CVD / OI / 开仓依据 / 失效位」——对读者是**92 次「我该不该动手」的重复询问**，
且每张都看不出「这是同一根 K 线、同一个下杀事件」。

**回答**：把「同 1h 根 + 同方向」的 BRK 破位（组规模 ≥5）在**渲染层**压成一张
**「市场级事件」卡**：一个事件、N 币、触发根、量比与涨跌幅区间、前 12 币清单。

**边界（本工单明确不做）**：
- **主池不合并**——主池信号是逐币 P↑OI↑ 独立判定（无 `bar=` 标签，线上实测 0 组同根），
  且各自带催化剂共振，合并会掩盖真实独立事件。
- **不抑制、不删行、不写库**——`alerted_at` / `detail` 快照 / 冷却 / 去重 / outcome
  统计全部**按币逐条保持现状**；合并只发生在**邮件正文渲染**。
- **标题与批级摘要仍按币数计数**（「92 币高置信信号」照旧），只把正文卡片数降下来。

## 2. 判据预登记（跑前锁死，见 §4 验收）

| 项 | 预登记值 | 依据 |
|---|---|---|
| 合并键 | `(bar= 标签, p_dir)`，且 `pool='accumulation' AND scenario='BRK'` | `bar=` 是生产去重已用的同根键（P2-7）；方向不同是不同事件 |
| 合并阈值 | **组规模 ≥ 5** | 线上只读实证（§8.1）：BRK 同根组规模分布**双峰**——n≤4 是常态（96 组，含 65 组 n=1），n≥5 是稀有事件区（7 组：5/7/7/9/18/33/92，覆盖 171 行 = 全量告警 20%），自然断点恰在 5 |
| 事件卡内容 | rank + 「市场级事件」+ 方向 + N 币 + 触发根（北京时间）+ 中位量比 + 涨跌幅区间 + 前 12 币 chips +「+N 币」 | 状态感知口径：读者第一眼看到「市场做了什么」，而非 N 次逐币询问 |
| 事件卡省略 | 成员卡不渲染共振/CVD/OI/开仓依据/失效位 | 事件卡的本质是「同根」，逐币属性属第二层信息 |
| **PASS 判据** | ① 通道③ 注入测试 ≥10 用例全 PASS；② 通道① 源码核验：DB 写入路径零改动、title/summary 仍按币数、单件/小批行为逐字不变；③ 通道② 线上只读：09-23T14（92 币）复算 → 1 事件卡 + 91 省略 | 三通道缺一不闭环 |

**不合并的显式清单**（判据测试用例）：
- 主池信号（无 `bar=`）→ 各自成卡；
- BRK 但无 `bar=` 标签 → 各自成卡；
- BRK 同 bar 但 `p_dir` 不同 → 各自成卡；
- 组规模 <5 → 各自成卡；
- 组规模 ≥5 但含非 BRK → 只合并 BRK 成员。

## 3. PR 级改动清单

单文件 `05_代码与脚本/scripts/bin/scan_daemon.py`：

1. **常量**：`MERGE_BRK_MIN = 5`（置于 SUPPRESS_BRK_SHORT 常量块附近，含分布依据注释）。
2. **纯函数** `_brk_bar_root(sig)`：从 `context_tags` 抽 `bar=` 根（UTC 字符串），无则 None。
3. **纯函数** `_brk_merge_plan(items, min_n)`：输入已按强度降序的 items，按
   `(pool=='accumulation' AND scenario=='BRK', bar_root, p_dir)` 分组，返回
   `{代表下标: [成员下标...]}`（代表 = 组内最强，因输入已降序 = 首个出现的下标），
   仅保留组规模 ≥ min_n。**纯函数**（不碰 DB / 全局），可注入测试。
4. **渲染** `_render_alert_email` 卡片循环：
   - 排序后计算 `merge_plan`；维护 `_merged_idx`（跳过成员）与 `card_no`（渲染卡号）。
   - 代表下标 → 渲染新函数 `_render_market_event_card(...)`（事件卡），成员全部跳过。
   - 非合并卡 → 原样渲染，仅 rank 改用 `card_no`（非合并批 `card_no == idx`，逐字不变）。
5. **事件卡渲染** `_render_market_event_card(...)`（新函数，纯本地 HTML 组装）。

**不在清单内**（禁止顺带改动）：`_alert_title`、`_render_batch_summary`、`_load_alert_candidates`、
候选循环、DB 写入段、任何阈值/判据。

### 8.1 线上只读实证：BRK 同根组规模分布（2026-10-02）

全量已告警 high = **839 行**；BRK 按 `(bar=, p_dir)` 分组共 **103 组**：


  次为 09-24T14 ↑ 33 币、09-30T12 ↑ 18 币。
