## ⚠️ 发现的问题

### 🔴 P1 — 导航 7 个 tab 却只有 6 个 section（明确瑕疵）

- **位置**：`index.html:2631-2632`；`kol.html:514-515`、`research.html:1426-1427` 复制了同一套 nav-tabs
- **现象**：`总览` 与 `资产库` **两个 tab 都指向 `#assets` / `data-section="assets"`**；而页面 section 实际只有 `assets/market/unlock/heat/backtest/tasks` 六个。
- **后果**：
  1. 滚到资产区时 **两个 tab 同时高亮**（IntersectionObserver 对两个同 `data-section` tab 都 `toggle('active', true)`）；
  2. 点击「总览」「资产库」无区别（同锚点）；
  3. 用户误以为有两个独立模块，实为同一区块。
- **根因**：`assets` section（`index.html:2644` 起）内部只有一个「📚 资产资料库」标题，并未真正拆出「总览」独立区块。
- **修法（二选一）**：
  - **方案 A（最小改动，推荐）**：删掉三处冗余的「总览」tab，仅保留「资产库」。
  - **方案 B（彻底）**：把 `assets` section 拆成 `<section id="overview">`（工作台标题+统计）与 `<section id="assets">`（搜索+资料），导航分别对应，JS `sections` 数组（`index.html:5719`）同步加 `'overview'`。

### 🟡 P2 — 后端全量限流在多 worker 下失效（一致性问题）

- **位置**：`app.py:47` `_feed_full_last_ts = 0.0`（模块级内存全局）被 `app.py:711-721` 的 5s 全量限流读写；`gunicorn_config.py:11` **默认 `workers = 2`**。
- **现象**：gunicorn fork 2 进程（且 `preload_app=True`），每个 worker 独立内存，A 的限流时间戳不约束 B → **全量限流形同虚设**。
- **矛盾点**：同文件 `recrawl_state` / `unlock_state` 均用 `_RecrawlFileLock` **文件锁持久化**跨进程共享，唯独全量限流未做，规范不一致。
- **影响**：单用户首页场景风险低（全量查询仅在 `latestTs=0` 首次发生），但上线 Zeabur（gunicorn 2 workers）后限流名存实亡。
- **修法（二选一）**：
  - **方案 A（与项目一致）**：把时间戳改文件持久化，复用现有 `_RecrawlFileLock` + json 文件模式（见下方代码）。
  - **方案 B（最简）**：直接去掉全量限流——增量查询无限流，全量仅首次触发、且单用户，限流价值本就有限，反而多 worker 下失效造成“假保护”错觉。

### 🟡 P2 — 前端 429 处理未退避、未读 `retry_after`

- **位置**：`index.html:5776` 收到 429 直接 `return null`。
- **现象**：
  1. `latestTs` 不前进（**这点正确**，避免丢数据）；
  2. 但**不读后端已返回的 `retry_after`**（`app.py:719` 已返回）；
  3. 下轮 timer 仍用 `pollInterval`（5790 行），**不加倍退避**（对比 5793-5794 网络错误分支有 `backoff×2`）。
- **影响**：正常流程因增量查询无限流、429 极少触发，但“限流契约”未闭环。
- **修法**：429 分支读 `retry_after` 并进位 backoff（见下方代码）。

### 🟢 P3 — 增量查询严格大于，极端漏日志（极低概率）

- **位置**：`app.py:737` `WHERE tl.created_at > to_timestamp(%s)`。
- **现象**：前端传 `latest_ts`，若同一微秒批量写入多条日志，时间戳 `=` `latest_ts` 的那条会被漏掉（下次 `since_ts` 已前进也不再返回）。
- **概率**：极低——`created_at` 带微秒精度、批量同戳极少。
- **修法**：改用 `>=` + 前端按 `(task_id, line_no)` 去重，双保险。

### P2 — 全量限流文件持久化（app.py）

在 `_feed_full_last_ts` / `_feed_full_lock` 定义处（`app.py:46-48`）替换为：
```python
import os as _os
_FEED_FULL_TS_FILE = RECRAWL_STATE_DIR / "feed_full_ts.json"
_FEED_FULL_TS_LOCK = RECRAWL_STATE_DIR / "feed_full_ts.lock"

def _load_feed_full_ts() -> float:
    try:
        with open(_FEED_FULL_TS_FILE) as f:
            return float(_os_json_load(f).get("ts", 0.0))
    except Exception:
        return 0.0

def _save_feed_full_ts(ts: float):
    import json as _json
    tmp = _FEED_FULL_TS_FILE.with_suffix(".tmp")
    with open(tmp, "w", encoding="utf-8") as f:
        _json.dump({"ts": ts}, f)
    _os.replace(tmp, _FEED_FULL_TS_FILE)
```
`api_scheduler_feed` 限流段（`app.py:712-721`）改为在 `_RecrawlFileLock(_FEED_FULL_TS_LOCK)` 内读写 `_load_feed_full_ts()` / `_save_feed_full_ts(now)`。

### P2 — 429 退避（index.html，替换 5776 行）

```javascript
if (r.status === 429) {
    return r.json().then(function (body) {
        var wait = (body && body.retry_after ? body.retry_after * 1000 : _scheduler.pollInterval);
        _scheduler.backoff = Math.min(_scheduler.backoff * 2, 8);
        _scheduler.timer = setTimeout(fetchSchedulerFeed, Math.max(wait, _scheduler.pollInterval * _scheduler.backoff));
        return null;
    }).catch(function () { return null; });
}
```
