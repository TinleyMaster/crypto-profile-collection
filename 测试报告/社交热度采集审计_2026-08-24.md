## 〇、一句话判语

采集**管道是通的**（有数据、有调度、有可解释性），但**有三个层级的问题**：
1. **最致命（P0）**：采回来的社交/KOL 数据**投研页根本看不到**——1149 行社交热度 + 31 条 KOL 喊单全躺在库里吃灰。
2. **置信度造假（P0）**：`confidence=high` 的记录 100% 缺 Twitter/Reddit 数据，置信度指标名不副实。
3. **方法学混淆（P1）**：把"行情热度"塞进"社交热度"、失效的 Reddit 源、长尾币 LLM 硬凑中性分——导致分数对长尾币基本是噪声。

## 一、当前采集方式（源码 + DB 实测）

### 1.1 社交热度 `biz.asset_social_heat`（1149 行，8-14~8-24 每日更新）
调用链：`db_stats.query_social_heat()`（先查缓存，未命中跑脚本）→ `scripts/bin/phase_c_social_heat.py` → 写库。

四维度加权综合评分（`SCORE_WEIGHTS`）：

| 维度 | 权重 | 数据来源 | 计算 |
|---|---|---|---|
| community | 0.25 | CoinGecko `community_data`（twitter/reddit/telegram 粉丝）+ github stars/forks | log10 归一化（cap: twitter 1e6 / reddit 1e6 / tg 1e5）取均值 |
| sentiment | 0.30 | Reddit 搜索 + CG `status_updates` + Google News RSS → **LLM(DeepSeek/豆包)** 情绪分 | LLM 直接给 0-100 |
| trend | 0.25 | CG `/search/trending` 热搜位次 + 新闻数量 | 位次 + 数量合成 |
| market | 0.20 | CG `market_data`（成交量/24h涨跌/市值排名） | 量/涨跌/排名合成 |

### 1.2 KOL 体系 `workbench/kol/`（独立 `/api/kol/*` + 独立 `/kol` 页面）
- `kol_profile` 仅 **1 行**（手工塞的 binance_square「首席操盘手日记」，follower_count/win_rate 全 NULL）
- `kol_post` 31 行、`kol_signal` 31 行（全绑定这 1 个号，内容为 Binance Square 喊单）
- `kol_signal.backtest_done = False`（**0 条回测验证**）

## 二、合理性评估

✅ **合理之处**
- 免费公开源选型（CG + Google News + LLM）作为起点正确。
- 加权 + log 归一化 + 缺失维度自动剔除重归一化，思路对。
- 降级容错完善：CG 无 key 公共 API 兜底、Reddit 失败静默降级、LLM 未配置跳过。
- `methodology_json` / `input_snapshot_json` 记录计算依据，可解释性佳。

❌ **不合理之处**
- **概念混淆**：`market` 权重 0.20 用的是行情量价，不是社交。一个币暴涨会拉高"社交热度分"，污染语义。
- **置信度语义错误**（见 P0-B）。
- **Reddit 源失效**：代码注释自承"无鉴权 JSON 近年常被 403/Cloudflare 拦截"。实际 sentiment 维度对绝大多数币只靠 Google News（长尾币几乎无新闻）→ 维度严重偏倚。
- **长尾币 LLM 硬凑分**：无文本时 LLM 按规则返回中性 50 分，制造"有情绪分"的假象。
- **调度成本**：每资产每次重算跑 CG×4 + News + Reddit + LLM，180s 超时，配额/成本/失败风险都高。

## 四、更好的实现方式

### 方案 A（改良现有，低成本）
1. 剥离 market 维度，社交热度 = community(0.4) + sentiment(0.4) + trend(0.2)。
2. confidence 重写为：有效数据源数 × 数据新鲜度 × 文本量 的加权可信度，核心社媒全空即封顶 medium。
3. 替换 Reddit 失效源 → X API / Telegram / LunarCrush。
4. 长尾无数据 → `score=null, confidence=insufficient`，投研页不展示"假 50 分"。
5. 调度收敛到 TOP500 + 自选 + 异动币，增量更新。

### 方案 B（专业级，高价值）
- 接入 **LunarCrush / Santiment / Glassnode** 社媒指标 API（提及量、情绪、影响力分布）。
- **KOL 真正落地**：抓取一批真实 KOL，做 `win_rate` 回测验证，作为可信任信号源（当前 0 回测=不可信）。
- 社交热度作为**每日变化检测（diff 引擎）的一个维度**接入——机器擅长发现"今天社交热度突变"，这正是系统已有 diff 引擎的复利点。

## 五、给 dev AI 的可执行修法（片段）

**P0-A 路由（示例，需并入 db_stats.py 的 research 路由组）：**
```python
@research_bp.route("/<int:asset_id>/social")
def research_social(asset_id):
    heat = get_asset_social_heat(asset_id)          # 读 biz.asset_social_heat
    signals = db.list_signals_by_asset(asset_id)    # 读 biz.kol_signal
    return jsonify({"social_heat": heat, "kol_signals": signals})
```

**P0-B confidence 修正（phase_c_social_heat.py compute_scores 内）：**
```python
# 旧：confidence = "high" if n >= 4 else ("medium" if n >= 3 else "low")
# 新：核心社媒全空则封顶 medium
core_social_empty = all(community.get(k) in (None, 0) for k in
                        ("twitter_followers","reddit_subscribers","telegram_channel_user_count"))
if core_social_empty and n < 4:
    confidence = "low" if n <= 2 else "medium"
elif n >= 4 and not core_social_empty:
    confidence = "high"
else:
    confidence = "medium"
```
