# 子工作流7｜项目文档抓取归档 -> `doc_asset`（节点级配置清单）

## 一、这条工作流的目标

这条子工作流的职责是：

**从** **`coin_basic`** **中读取项目入口链接，发现 PDF / 白皮书 / 审计报告 / docs 下载文件，完成下载、去重、归档、双端上传，并写入** **`doc_asset`。**

最终产出两类结果：

- 原始文件归档到 `Google Drive`
- 知识化文件同步到 `ima知识库`
- 文件元数据和同步状态写回 PostgreSQL `doc_asset`

## 二、这条工作流的最终定位

### 做什么

- 读取 `coin_basic` 中的 `official_website / docs_url / github_url`
- 抓取页面内候选 PDF 链接
- 下载二进制文件
- 计算 `content_hash`
- 识别 `doc_type`
- 按 `cmc_id` 归档到固定币种目录
- 上传 `Google Drive + ima知识库`
- 幂等写入 `doc_asset`

### 不做什么

- 不生成行情数据
- 不修改 `coin_basic` 的主字段
- 不依赖大模型猜测事实类 URL
- 不按 `coin_symbol` 单独做唯一目录键

## 三、前置依赖

### 1）数据库前提

需要已有下列表：

- `coin_basic`
- `doc_asset`
- `sys_run_log`

其中：

- `coin_basic` 主键为 `cmc_id`
- `doc_asset` 使用 `content_hash` 作为主去重键

### 2）云端前提

- 已配置好 `Google Drive` 凭证
- 已确认 `ima知识库` 上传方式
- 已准备 `DeepSeek API Key`（用于分析非直链页面）

说明：

- 如果 `ima知识库` 暂时没有可直接调用的开放 API，这条工作流先保留 `HTTP_IMA_UPLOAD` 作为抽象节点
- 后续可以替换为 HTTP 接口、内部网关，或半自动上传步骤
- `DeepSeek` 只用于分析入口页、辅助提取文件直链或网页正文，不参与事实字段生成

### 3）目录前提

固定目录规则：

```text
CryptoResearch/{coin_symbol}__cmc_{cmc_id}/
```

固定子目录：

- `01_overview/`
- `02_official_docs/`
- `03_whitepaper/`
- `04_audit/`
- `05_github_exports/`
- `99_archive/`

## 四、工作流总链路

```text
When executed by another workflow
-> PG_READ_COIN_BASIC_DOC_SOURCES
-> Code_BUILD_SOURCE_QUEUE
-> Loop Over Items_SOURCE_QUEUE
-> Code_CLASSIFY_ENTRY_URL
-> IF_ENTRY_IS_DIRECT_PDF
  -> true  -> HTTP_DOWNLOAD_BINARY
           -> Code_HASH_CLASSIFY_ROUTE
           -> PG_CHECK_DOC_ASSET_BY_HASH
           -> IF_DOC_EXISTS
             -> true  -> PG_UPSERT_DOC_ASSET_EXISTING
             -> false -> GDRIVE_ENSURE_MAIN_FOLDER
                      -> GDRIVE_ENSURE_SUB_FOLDER
                      -> GDRIVE_UPLOAD_FILE
                      -> HTTP_IMA_UPLOAD
                      -> PG_UPSERT_DOC_ASSET_NEW
  -> false -> HTTP_FETCH_ENTRY_PAGE
           -> HTTP_DEEPSEEK_ANALYZE_PAGE
           -> Code_PARSE_DEEPSEEK_RESULT
           -> IF_AI_FOUND_DOWNLOAD_TARGET
             -> true  -> IF_AI_TARGET_IS_FILE
                      -> true  -> HTTP_DOWNLOAD_BINARY
                               -> Code_HASH_CLASSIFY_ROUTE
                               -> PG_CHECK_DOC_ASSET_BY_HASH
                               -> IF_DOC_EXISTS
                                 -> true  -> PG_UPSERT_DOC_ASSET_EXISTING
                                 -> false -> GDRIVE_ENSURE_MAIN_FOLDER
                                          -> GDRIVE_ENSURE_SUB_FOLDER
                                          -> GDRIVE_UPLOAD_FILE
                                          -> HTTP_IMA_UPLOAD
                                          -> PG_UPSERT_DOC_ASSET_NEW
                      -> false -> Code_BUILD_WEBPAGE_SNAPSHOT_FILE
                               -> Code_HASH_CLASSIFY_ROUTE
                               -> PG_CHECK_DOC_ASSET_BY_HASH
                               -> IF_DOC_EXISTS
                                 -> true  -> PG_UPSERT_DOC_ASSET_EXISTING
                                 -> false -> GDRIVE_ENSURE_MAIN_FOLDER
                                          -> GDRIVE_ENSURE_SUB_FOLDER
                                          -> GDRIVE_UPLOAD_FILE
                                          -> HTTP_IMA_UPLOAD
                                          -> PG_UPSERT_DOC_ASSET_NEW
             -> false -> IF_CAN_RETRY_DEEPSEEK
                      -> true  -> Code_PREPARE_NEXT_HOP_URL
                               -> HTTP_FETCH_ENTRY_PAGE
                      -> false -> NOOP_SKIP_UNRESOLVED_PAGE
-> PG_LOG_RUN_SUMMARY（可选）
```

## 六、节点级详细配置

## 节点1：`When executed by another workflow`

### 节点类型

`Execute Workflow Trigger`

### 作用

- 让这条工作流被主调度工作流或手动测试工作流调用

### 输入参数建议

支持可选输入：

- `target_cmc_id`
- `force_rescan`
- `max_ai_hops`

说明：

- `target_cmc_id` 用于单项目调试
- `force_rescan = true` 时允许重扫历史入口页
- `max_ai_hops` 用于限制 DeepSeek 最多连续分析多少跳页面，建议默认 `3`

## 节点2：`PG_READ_COIN_BASIC_DOC_SOURCES`

### 节点类型

`Postgres`

### 推荐 Operation

`Execute Query`

### 推荐 SQL

```sql
SELECT
    cmc_id,
    coin_symbol,
    coin_name,
    defillama_slug,
    official_website,
    docs_url,
    github_url
FROM coin_basic
WHERE track_status = '跟踪中'
  AND (
        official_website IS NOT NULL
        OR docs_url IS NOT NULL
        OR github_url IS NOT NULL
      )
  AND (
        {{ !$json.target_cmc_id ? 'TRUE' : 'cmc_id = ' + $json.target_cmc_id }}
      )
ORDER BY cmc_id;
```

### 输出字段

- `cmc_id`
- `coin_symbol`
- `coin_name`
- `defillama_slug`
- `official_website`
- `docs_url`
- `github_url`

## 节点3：`Code_BUILD_SOURCE_QUEUE`

### 节点类型

`Code`

### 作用

- 把每个项目的三个入口地址展平成任务队列
- 为后面每条入口附带来源类型

说明：

- `coin_basic` 表里没有 `entry_url` 这个字段
- 这里的入口 URL 是在本节点里由 `official_website / docs_url / github_url` 临时组装出来的中间字段
- 为避免和数据库字段混淆，下面统一命名为 `source_entry_url`

### 可直接粘贴代码

```javascript
const out = [];

for (const item of items) {
  const row = item.json;

  const sources = [
    { source_type: 'official_website', source_entry_url: row.official_website },
    { source_type: 'docs_url', source_entry_url: row.docs_url },
    { source_type: 'github_url', source_entry_url: row.github_url }
  ];

  for (const source of sources) {
    if (!source.source_entry_url) continue;

    out.push({
      json: {
        cmc_id: row.cmc_id,
        coin_symbol: row.coin_symbol,
        coin_name: row.coin_name,
        defillama_slug: row.defillama_slug,
        source_type: source.source_type,
        source_entry_url: source.source_entry_url,
        force_rescan: $json.force_rescan ?? false,
        ai_hop_count: 0,
        max_ai_hops: $json.max_ai_hops ?? 3
      }
    });
  }
}

return out;
```

### 输出字段

- `cmc_id`
- `coin_symbol`
- `coin_name`
- `defillama_slug`
- `source_type`
- `source_entry_url`
- `ai_hop_count`
- `max_ai_hops`

说明：

- 这个节点 `return out;` 之后，输出已经是“多条 item”
- 因此这里**不需要** **`Split Out`**
- 如果希望逐条串行执行、控制抓取节奏，应该接 `Loop Over Items`

## 节点4：`Loop Over Items_SOURCE_QUEUE`

### 节点类型

`Loop Over Items`

### 作用

- 把入口 URL 队列按 1 条 1 条串行处理
- 避免同时抓取过多站点页面

### 配置建议

- Batch Size: `1`
- 勾选或启用串行循环语义

说明：

- `Code_BUILD_SOURCE_QUEUE` 的输出本身已经是一条条 item
- 这里使用 `Loop Over Items` 的目的不是“拆数组”，而是“控制执行节奏”
- 如果你后续验证发现并不需要串行限流，这个节点也可以删除，直接把 `Code_BUILD_SOURCE_QUEUE` 连接到 `Code_CLASSIFY_ENTRY_URL`

## 节点5：`Code_CLASSIFY_ENTRY_URL`

### 节点类型

`Code`

### 作用

- 判断当前入口 URL 是否可以直接下载
- 把入口分成“PDF 直链”和“需要继续分析的页面入口”

### 判断逻辑建议

- `direct_pdf`：明确以 `.pdf` 结尾，或明显是文件直链
- `html_page`：普通官网页、docs 首页、带锚点页面
- `github_repo`：GitHub 仓库或目录页
- `file_share_page`：如 `docsend` 之类的承载页
- `unknown`：暂时无法识别

### 可直接粘贴代码

```javascript
function classifyEntryUrl(url) {
  const lower = (url || '').toLowerCase();

  if (!lower) return 'unknown';

  if (
    lower.endsWith('.pdf') ||
    lower.includes('.pdf?') ||
    lower.includes('/wp-content/uploads/') && lower.includes('.pdf') ||
    lower.includes('firebasestorage.googleapis.com') && lower.includes('.pdf') ||
    lower.includes('/assets/documents/') && lower.includes('.pdf')
  ) {
    return 'direct_pdf';
  }

  if (lower.includes('github.com/')) return 'github_repo';
  if (lower.includes('docsend.com')) return 'file_share_page';
  if (lower.startsWith('http://') || lower.startsWith('https://')) return 'html_page';

  return 'unknown';
}

return items.map(item => ({
  json: {
    ...item.json,
    entry_kind: classifyEntryUrl(item.json.source_entry_url)
  }
}));
```

### 输出字段

- `entry_kind`

建议值：

- `direct_pdf`
- `html_page`
- `github_repo`
- `file_share_page`
- `unknown`

## 节点6：`IF_ENTRY_IS_DIRECT_PDF`

### 节点类型

`IF`

### 作用

- 判断当前入口是否走直链下载通道

### 推荐条件

左值：

```text
{{$json.entry_kind}}
```

规则：

- `equals direct_pdf`

### 分支说明

- `true`：直接进入 `HTTP_DOWNLOAD_BINARY`
- `false`：进入 `HTTP_FETCH_ENTRY_PAGE`

说明：

- 这是这条工作流最重要的分流节点
- 你数据库里这 3 个字段本质上是“入口地址字段”，不是“文件地址字段”
- 只有明确为 PDF 直链时，才应该直接下载

## 节点7：`HTTP_FETCH_ENTRY_PAGE`

### 节点类型

`HTTP Request`

### Method

`GET`

### URL

```text
{{$json.source_entry_url}}
```

### 关键配置

- Response Format: `String`
- Follow Redirects: `true`
- Ignore SSL Issues: `false`
- Timeout: `30000`

### Headers 建议

```text
User-Agent: Mozilla/5.0 (compatible; n8n-doc-bot/1.0)
Accept: text/html,application/xhtml+xml,application/xml;q=0.9,*/*;q=0.8
```

### 输出字段

- `body` 或 `data`

说明：

- 不同版本 n8n 的 HTML 返回字段名可能不同，后面代码节点统一兜底读取

## 节点8：`HTTP_DEEPSEEK_ANALYZE_PAGE`

### 节点类型

`HTTP Request`

### 作用

- 调用 `DeepSeek` 分析 HTML 页面
- 输出两类候选结果：
  - 可直接下载的文件 URL
  - 可归档的网页正文内容
  - 如果当前页还不够，可返回“下一跳候选页面”

### Method

`POST`

### URL

```text
https://api.deepseek.com/chat/completions
```

### Headers

```text
Authorization: Bearer {{ $env.DEEPSEEK_API_KEY }}
Content-Type: application/json
```

### Body Content Type

`JSON`

### 推荐 Body

```json
{
  "model": "deepseek-chat",
  "temperature": 0,
  "response_format": {
    "type": "json_object"
  },
  "messages": [
    {
      "role": "system",
      "content": "你是网页文档提取助手。只做页面分析，不补充虚构事实。请从输入网页内容中判断是否存在可下载文件链接、可直接归档的网页正文，或最值得继续追踪的下一跳页面。如果找不到，请明确返回未找到。输出必须是 JSON。"
    },
    {
      "role": "user",
      "content": "请分析这个入口页。当前是第 {{$json.ai_hop_count || 0}} 跳，最多允许 {{$json.max_ai_hops || 3}} 跳。输出 JSON，字段固定为：found_target(boolean), target_type(file|webpage|none), download_url(string), webpage_title(string), webpage_content(string), doc_type(string), next_url(string), should_continue(boolean), reason(string)。入口URL: {{$json.source_entry_url}}\n\n网页HTML如下：\n{{$json.body ?? $json.data ?? $json.response ?? ''}}"
    }
  ]
}
```

### 输出要求

- DeepSeek 只允许做“页面分析和提取”
- 不允许让 AI 猜 URL、猜白皮书标题、猜项目资料
- 识别不出来就返回 `target_type=none`
- 如果当前页没有答案，但存在明显下一跳入口，可返回 `next_url`
- `next_url` 必须来自当前页面内容，不允许编造
- 建议最多允许 `2-4` 跳，默认 `3`

## 节点9：`Code_PARSE_DEEPSEEK_RESULT`

### 节点类型

`Code`

### 作用

- 解析 DeepSeek 返回 JSON
- 统一输出 `ai_found_target / ai_target_type / ai_download_url / ai_webpage_content / ai_next_url`

### 可直接粘贴代码

```javascript
const row = $json;
const raw = row.choices?.[0]?.message?.content ?? '{}';

let parsed;
try {
  parsed = JSON.parse(raw);
} catch {
  parsed = {
    found_target: false,
    target_type: 'none',
    download_url: '',
    webpage_title: '',
    webpage_content: '',
    doc_type: '',
    next_url: '',
    should_continue: false,
    reason: 'deepseek_json_parse_failed'
  };
}

return [{
  json: {
    ...row,
    ai_found_target: parsed.found_target === true,
    ai_target_type: parsed.target_type ?? 'none',
    ai_download_url: parsed.download_url ?? '',
    ai_webpage_title: parsed.webpage_title ?? '',
    ai_webpage_content: parsed.webpage_content ?? '',
    ai_doc_type: parsed.doc_type ?? '',
    ai_next_url: parsed.next_url ?? '',
    ai_should_continue: parsed.should_continue === true,
    ai_reason: parsed.reason ?? ''
  }
}];
```

## 节点10：`IF_AI_FOUND_DOWNLOAD_TARGET`

### 节点类型

`IF`

### 作用

- 判断 DeepSeek 是否成功识别出可归档目标

### 推荐条件

左值：

```text
{{$json.ai_found_target}}
```

规则：

- `equals true`

### 分支说明

- `true`：继续处理
- `false`：先判断是否继续多跳分析，再决定是否跳过

## 节点10A：`IF_CAN_RETRY_DEEPSEEK`

### 节点类型

`IF`

### 作用

- 判断 DeepSeek 是否还有继续分析下一跳页面的预算

### 推荐条件

左值：

```text
{{ $json.ai_should_continue && $json.ai_next_url && (($json.ai_hop_count || 0) < ($json.max_ai_hops || 3)) }}
```

规则：

- `equals true`

### 分支说明

- `true`：进入下一跳页面抓取
- `false`：直接跳过

### 建议

- 默认 `max_ai_hops = 3`
- 如果页面结构特别复杂，可临时提到 `4`
- 不建议无限循环

## 节点10B：`Code_PREPARE_NEXT_HOP_URL`

### 节点类型

`Code`

### 作用

- 把 DeepSeek 给出的 `next_url` 设为新的 `source_entry_url`
- 累加 hop 计数，继续回到 `HTTP_FETCH_ENTRY_PAGE`

### 可直接粘贴代码

```javascript
return items.map(item => ({
  json: {
    ...item.json,
    source_entry_url: item.json.ai_next_url,
    ai_hop_count: (item.json.ai_hop_count || 0) + 1
  }
}));
```

### 输出字段

- `source_entry_url`
- `ai_hop_count`

说明：

- 这个节点只负责“准备下一跳”
- 下一跳仍然复用同一套 `HTTP_FETCH_ENTRY_PAGE -> HTTP_DEEPSEEK_ANALYZE_PAGE -> Code_PARSE_DEEPSEEK_RESULT` 链路
- 如果 DeepSeek 还是没找到目标，就继续受 `max_ai_hops` 限制

## 节点11：`IF_AI_TARGET_IS_FILE`

### 节点类型

`IF`

### 作用

- 判断 AI 识别到的是“文件链接”还是“网页正文”

### 推荐条件

左值：

```text
{{$json.ai_target_type}}
```

规则：

- `equals file`

### 分支说明

- `true`：走文件下载
- `false`：按网页内容归档

## 节点12：`Code_BUILD_WEBPAGE_SNAPSHOT_FILE`

### 节点类型

`Code`

### 作用

- 把 AI 提取出的网页正文封装成可上传文件
- 推荐保存为 `.md`

### 可直接粘贴代码

```javascript
const row = $json;
const content = `# ${row.ai_webpage_title || row.coin_name || 'Untitled'}\n\nSource: ${row.source_entry_url}\n\n${row.ai_webpage_content || ''}`;
const fileName = `${row.coin_symbol}_${row.ai_doc_type || 'webpage'}_snapshot_unknown_${new Date().toISOString().slice(0,10).replace(/-/g, '')}.md`;

return [{
  json: {
    ...row,
    candidate_url: row.source_entry_url,
    doc_type: row.ai_doc_type || 'webpage',
    mime_type: 'text/markdown',
    file_name: fileName
  },
  binary: {
    data: {
      data: Buffer.from(content, 'utf8').toString('base64'),
      mimeType: 'text/markdown',
      fileName
    }
  }
}];
```

## 节点13：`HTTP_DOWNLOAD_BINARY`

### 节点类型

`HTTP Request`

### Method

`GET`

### URL

```text
{{$json.ai_download_url || $json.candidate_url || $json.source_entry_url}}
```

## 节点14：`Code_HASH_CLASSIFY_ROUTE`

### 节点类型

`Code`

### 作用

- 读取二进制内容
- 计算 `content_hash`
- 识别 `doc_type`
- 生成文件名
- 生成 Drive / ima 子目录

### 可直接粘贴代码

```javascript
const crypto = require('crypto');

function detectDocType(url) {
  const lower = (url || '').toLowerCase();

  if (lower.includes('audit')) return 'audit';
  if (lower.includes('whitepaper') || lower.includes('litepaper')) return 'whitepaper';
  if (lower.includes('tokenomics')) return 'tokenomics';
  if (lower.includes('deck') || lower.includes('pitch')) return 'deck';
  if (lower.includes('docs')) return 'docs';
  return 'research';
}

function mapSubfolder(docType, sourceType) {
  if (docType === 'audit') return '04_audit';
  if (docType === 'whitepaper' || docType === 'tokenomics') return '03_whitepaper';
  if (sourceType === 'github_url') return '05_github_exports';
  return '02_official_docs';
}

function safeDomain(url) {
  try {
    return new URL(url).hostname.replace(/^www\\./, '');
  } catch {
    return 'unknown-domain';
  }
}

const row = $json;
const binary = items[0].binary?.data;

if (!binary?.data) {
  throw new Error('binary.data 不存在，无法计算哈希');
}

const buffer = Buffer.from(binary.data, 'base64');
const contentHash = crypto.createHash('sha256').update(buffer).digest('hex');
const urlForDetect = row.ai_download_url || row.candidate_url || row.source_entry_url;
const docType = row.doc_type || row.ai_doc_type || detectDocType(urlForDetect);
const subfolder = mapSubfolder(docType, row.source_type);
const sourceDomain = safeDomain(urlForDetect).replace(/[^a-zA-Z0-9.-]/g, '_');
const versionTag = row.version_tag || 'unknown';
const dateTag = new Date().toISOString().slice(0, 10).replace(/-/g, '');
const extension = binary.mimeType === 'text/markdown' ? 'md' : 'pdf';
const fileName = row.file_name || `${row.coin_symbol}_${docType}_${sourceDomain}_${versionTag}_${dateTag}.${extension}`;
const mainFolder = `CryptoResearch/${row.coin_symbol}__cmc_${row.cmc_id}`;

return [{
  json: {
    ...row,
    doc_type: docType,
    resolved_url: urlForDetect,
    mime_type: binary.mimeType || row.mime_type || 'application/pdf',
    file_size_bytes: buffer.length,
    content_hash: contentHash,
    source_domain: sourceDomain,
    version_tag: versionTag,
    drive_folder_path: `${mainFolder}/${subfolder}`,
    ima_folder_path: `${mainFolder}/${subfolder}`,
    file_name: fileName
  },
  binary: items[0].binary
}];
```

### 输出字段

- `doc_type`
- `content_hash`
- `file_name`
- `drive_folder_path`
- `ima_folder_path`
- `file_size_bytes`

## 八、推荐的首轮测试顺序

### 1）先只测单项目

建议先传：

```text
target_cmc_id = 29481
```

先验证：

- 是否能抓到官网入口页
- 是否能抽出候选 PDF
- 是否能算出 `content_hash`
- 是否能写入 `doc_asset`

### 2）再测 Drive

优先确认：

- 币种主目录是否正确
- 子目录是否正确
- 文件名是否符合规范

### 3）最后接 ima

原因：

- `Google Drive` 更适合先验证原始文件归档
- `ima知识库` 上传接口通常比 Drive 更不确定

## 九、最小验收标准

满足下面 6 条，就算子工作流7第一版跑通：

1. 能从 `coin_basic` 正常读取项目入口 URL
2. 能发现至少 1 个有效 PDF 候选链接
3. 能下载文件或生成网页快照并算出 `content_hash`
4. 能把文件上传到 `Google Drive` 正确币种目录
5. 能把记录写进 `doc_asset`
6. 重复运行不会产生重复文件记录
