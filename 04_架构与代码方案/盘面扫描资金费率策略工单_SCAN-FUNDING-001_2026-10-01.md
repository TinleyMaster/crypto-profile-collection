## 1. 结论先行（本工单要回答什么）

**假设 H1（funding fade / 逼空反转）**：资金费率是**持仓拥挤度**的连续度量。
极端**负**费率 = 空头拥挤（空头付钱养多头）⇒ 后续价格**反弹**（逼空）；
极端**正**费率 = 多头拥挤 ⇒ 后续价格**回落**。
对应操作：极端负费率 → **做多**；极端正费率 → **做空**。

**为什么怀疑它有戏（数据面先验，非事后挑数）**：`biz.funding_rate_hist` 现口径下分布**严重负偏**——
min **−2.000%** / max **+0.366%** / 均值 −0.0045% / p5 **−0.0344%** / p50 +0.005% / p95 +0.018%；
`rate ≥ +0.05%` 仅 **1,154** 条，而 `rate ≤ −0.05%` 有 **4,231** 条、`≤ −0.1%` 有 **2,477** 条
（负极端值**数量是正的 3.7 倍、幅度 5 倍**）。该先验来自**分布本身**，在看到任何收益数字**之前**写下。
另：`phase_scan_accumulation_pool.py::detect_acc` 早有标签「OI↑ + 费率偏低/负：偏逼空潜力」，
但 funding **从未当主信号验证过**（A3 只把 funding 当过「滤镜」做消融，不是独立策略）。

### 1.1 预登记判据（**开工前锁死，禁止事后调整**）

| 项 | 取值 | 选择理由（先验） |
|---|---|---|
| 分位窗口 N | **21 个结算点（= 7 天 × 3/日）** | 长于 7 天的窗口对 105 天可用价格史来说样本折损过大；短于 7 天的窗口分位噪声高。7 天覆盖完整周周期，结算点足够多（21 个）使分位稳定。**此值锁定，不因结果调整。** |
| 触发阈值 | **分位 ≤ 0.10 → 做多；分位 ≥ 0.90 → 做空** | 对称、可解释；用分位数而非绝对费率阈值 ⇒ **不引入样本内选参自由度**（费率量纲随币种/时期漂移，绝对阈值必然要挑）。 |
| 分位口径 | `count(window 内严格小于当前值的个数) / (window 长度 − 1)` | 用 `n−1` 作分母使 0.10/0.90 两侧**严格对称**（各取 3/21）。 |
| 主持有期 H | **24h** | 与项目既有主口径一致（§8.1.7 / §8.1.9 / A3 均以 24h 为主窗口），便于横向对照；且 24h 跨 3 个结算点，能吃到费率 carry。 |
| 成本 | **双边 taker 0.1%**，方向对齐**之后**扣 | 与 `collect_scan_outcome.py::aligned_ret` 同口径（`signed − cost`，防止空头虚增）。 |
| 切分 | **时序切分**：test = 最近 **21 天**（上海日），其余为 train | 预登记，不做随机切分（时序泄漏）。 |
| 样本门槛 | 任一侧（train/test）**≥ 50 笔且 ≥ 5 独立日**，不足则判 `insufficient` | 防小样本下结论。 |
| 显著性口径 | **按日等权聚类 t**（非按笔） | §8 既定纪律：按笔与按日可反号，判显著性一律看日 t。 |

**PASS（H1 成立）**——以下**全部**满足：
1. **合并两侧**（做多 ∪ 做空，按方向对齐）的 24h 净均，**train 与 test 双侧均 > +0.20%**（覆盖双边成本后仍有正期望）；
2. 双侧**按日聚类 t > 0**；
3. **防 beta 闸门**：合并净均 **− 无条件基线净均（always-long）> 0**，且**双侧成立**（否则只是「上涨 regime 里做多」）。

**FAIL**——任一侧反向（净均 ≤ +0.20% 或日 t ≤ 0 或超额 ≤ 0）⇒ 按 §14.4 纪律，
**不得进入模拟盘、不得改任何线上代码**，如实记录并回到方向选择。

**稳健性（仅描述，不参与判定）**：N=9（3d）/ N=42（14d）；阈值 p5/p95；H=1h/4h/12h/72h；
**多头侧 / 空头侧分列**（用于判断是否只是 beta）。

## 6. 风险与预期管理

1. **上涨 regime 陷阱（最大风险）**：可用价格史仅 **105 天（2026-06-18 → 10-01）**，且**单边上涨**。
   「极端负费率 → 做多」在这种样本里**天然占便宜**（做多本身就在涨），train/test 同在上涨 regime
   **切不出跨 regime 对照**（§12.1-A3 (b) 已预警）。⇒ §1.1 的**防 beta 闸门（判据 3）**就是为它设的；
   若 H1 通过但**超额 ≤ 0**，结论只能是「等于 beta」而非「有 alpha」。
2. **信号重叠**：费率 8h 结算（部分币 4h），而持有期 24h ⇒ 相邻结算点的持仓窗口大量重叠，
   按笔 n 被系统性高估。⇒ 与既有工单同法，**一律看按日聚类 t**。
3. **数据面**：funding 191 币 × 105 天可用 ≈ **93,000 个结算点**；1h K 线仅回溯至 06-18，
   故 funding 本身虽回溯 181 天（04-03 起），**能用价格结算的只有后 105 天**——这是本工单的**硬边界**，
   无法靠延长回看绕过。
4. **结算点非整点币种**：个别币为 4h 费率（每符号最多 729 个结算点），与 8h 币混池时
   「每符号结算点数」不齐 ⇒ 一律**逐符号**算分位、**逐笔**归一化，不做跨符号对齐。
5. **funding carry 未计入**：本回测只算**价格 PnL − 手续费**，不含「持仓期间收到的费率」。
   由于方向与费率符号天然同侧（负费率做多 = 收钱），实际经济性**优于**本回测读数 ⇒ 本口径是**保守**的。

## 8. 验证结论（2026-10-01 已闭环，prod 真实数据 run）

**结论【FAIL】：H1（极端负费率 → 反弹）不成立，且方向为负。**
按 §1.1 预登记判据关闭，**不进入模拟盘、不改任何线上代码**。

### 8.1 样本与口径

| 项 | 读数 |
|---|---|
| 价格窗 | 2026-06-18 07:00 → 2026-09-28 12:00 UTC（受 1h K 线起点限制） |
| 可结算结算点 / 有效样本 | 93,132 → **93,107 点**，191 符号，103 个独立日 |

N=9 train −0.117%（t −0.62）/ test −0.505%（t −0.97）；N=42 train −0.061%（t −0.79）/ test −0.170%（t −0.15）。
⇒ **不是窗口选择问题**。

### 8.3 ⚠️ 口径修正：tie-naive → tie-aware（**必须留档**）

首跑用 §1.1 原式 `count(win 内 < x) / (n−1)`，结果**标出 41% 的点为做多**（预登记意图是 ~10%）。
根因：`biz.funding_rate_hist` 有 **45,984 / 109,364（42%）条 == 0.00005**——即 **Binance 默认费率**，
是**中性值而非极端值**；tie-naive 下任何落在该众数上的点都「窗口内最小」⇒ 分位≈0 ⇒ 被误判为「极端负费率」。
改用 tie-aware 均秩式 `(count(<x) + 0.5·count(==x)) / n` 后触发占比回到 **7.7% / 5.9%**。

**这是口径修正（原式未实现预登记意图），不是调参**：N=21 / 阈值 0.10·0.90 / H=24 / 切分 全部未动。
**且两种口径结论一致为 FAIL**（tie-naive 合并 24h：train +0.376% 超额 −0.121pp、test +0.606% 超额 −0.246pp，
同样卡在「防 beta 闸门」）⇒ 修正不改变判决、只改变读数。

### 8.4 本次真正学到什么（比 FAIL 本身更重要）

1. **「极端负费率 → 反弹」在本样本上不但无效，而且略有反向。**
   多头桶 24h 净均 +0.044%（≈ 打平手续费），**比「无脑做多」低 0.53pp**；
   test 段更是 −0.164%。即极端负费率标的的后续表现**弱于平均**，不是强于。
2. **防 beta 闸门是本次唯一真正起作用的判据。** 若只看「合并净均 > +0.2% 且 t>0」，
   tie-naive 版本（+0.376t/+0.606t、日 t +1.84/+1.40）**会被误判为 PASS**——
   而它相比「什么都不筛、直接做多」是**负超额**。这验证了 §1.1 判据 3 的必要性。
3. **单边上涨 regime 下，「任何做多条件」都会看起来像盈利。** 基线本身 24h 就有 +0.577%；
   只有相对基线的超额才有信息量。这与 §12.1-A3 (b) 的预警完全一致。
4. **funding 是「描述拥挤」的好指标，但不是「预测反转」的好信号**——至少在这 105 天里不是。
