## 0. 结论先行

上游方案的**方向正确**——把单一标量确定性拆成短/中/长三档、把 missing 转成「补什么能到哪」、承认 Launchpool 类长期结构性不可达，这三点都对且值得做。

但按上游方案的 Phase 顺序（P0→P1→P2→P3）开工，**会在 P1 就卡死**，且它的验收标准内部互斥。本文的修订是：

1. **分档的本质是分证据来源，不是给同一个分数改权重。** 这是解开「39.9 封顶 vs 短期档 ≥60」矛盾的唯一出路。
2. **期限标签零 LLM 改动即可拿到**——现有 `/→kind` 与 material→dimension 映射已经足够推导期限。
3. **P0 板块重分类的做法要改**：现有赛道分类体系里**没有 `launchpad` 枚举**（`sector.py:411` 刻意把 DL 的 launchpad 归入 defi），上游「sector → Launchpad」的验收无法通过。改为「保留来源 category，竞品池按 category 匹配」。
4. **「上线前用回测钉死阈值」这一步客观做不到**，改为阈值标注 `uncalibrated` 上线 + 新建 thesis 级前向跟踪表作为后续校准基建。

## 1. 上游方案的四处不可落地（附代码证据）

### 1.1 致命：验收 #3 与 #7 互斥

| 上游条款 | 内容 |
|---|---|
| §4 衔接铁律 | 「evidence 子分永远先过 39.9 封顶」 |
| 验收 #7 | 注入 28 条空 URL 引用 ⇒ 仍回落 39.9 |
| 验收 #3 | PONS **短期档应 ≥ 60** |

代码事实：`coverage` 来自 LLM 论点有效引用率（`db_stats.py:4315-4342`），PONS 22 点 0 有效引用 → `coverage = 0`；`coverage == 0` 时无条件打 `_ZERO_EVIDENCE_SCORE_CAP = 39.9`（`db_stats.py:4437-4440`，常量定义 `db_stats.py:4249-4256`）。

`coverage` **不分档**。三档共用同一个 coverage，则三档全被压到 39.9，`39.9 < 60`，**短期档闸门永远打不开**——上游方案的核心目标（告诉用户「短期能不能动」）直接落空。

> 根因：论点没有期限标签，且**「引用可核验」口径不适合量化数据**。「CVD 24h = +6.8%，2 小时前采集」不是推断，是测量；用「有没有 URL 引用」去否证一条链上测量值，是口径错配。

### 1.2 「复用四维、只调权重」在语义上不成立

上游 §2.1 给三档配了不同权重，但四个维度本身没有期限结构：

| 维度 | 实际读的数据 | 实现位置 | 期限属性 |
|---|---|---|---|
| consistency | funding_rate / oi_change_24h / cvd_24h | `db_stats.py:4368-4399` | **纯 T+0** |
| freshness | market / unlock / derivatives 的 age | `db_stats.py:4345-4365` | 短线视角 |
| sample | 资料完整度 present/total | `db_stats.py:4402-4408` | 跨期限 |
| coverage | 论点引用率 | `db_stats.py:4318-4342` | 跨期限 |

给长期档 0.15 的 consistency 权重，喂进去的还是 24h 资金费率——不是「长期信号一致性」，是短线的错位投影。**改权重不能凭空造出期限信息**；必须每档独立定义输入集。

### 1.3 「用 backtest_opportunities.py 回测校准阈值」做不到

上游 §9 把回测列为上线前置。但：

- 该框架 `SIGNAL_HORIZONS` 最长 30 天（catalyst `[7,14,30]`），其余多为 `[1,7]`（`backtest_opportunities.py:45-68`）；而快照全史仅约 25 天。
- 仓库内既有诊断脚本已自证此路不通：`diag_backtest_tier_hit_20260926.py:232-245` 打印「HIGH 档无样本：无法验证『HIGH=高确定性』…未做两比例显著性检验，勿据此宣称统计显著」。
- 更根本：该框架回测对象是 `biz.market_overview_snapshot` 里的 opportunity（signal_type/direction/target），**不是 `biz.research_thesis`**。投研页结论没有任何前向收益跟踪链路。

⇒ M（2–12 周）/L（季度–年）两档的阈值，**当前无任何数据可校准**。只能先当经验初值 + 显式标注未校准。

### 1.4 校准「抬升」的实证基础弱于描述

上游 P2 要把 catalyst 77.8% 当「已校准背书」写进中期 evidence。但：

- `market_rules.yaml:77` → `exempt_allow_high: []`；
- `market_rules.yaml:100` 注释明写：回测无 HIGH 样本（MED=29 / LOW=481），**无法按 tier 校准**。

77.8% 只是 signal_type 层的整体命中率，未按 tier 分层、未做显著性检验。包装成「已校准背书」恰是本项目防骗逻辑要防的事。可引用，但文案必须写全口径。

## 2. 修订后的核心设计

### 2.1 分档 = 分证据来源（口径分离）★ 解开 39.9 矛盾

| 档位 | 证据来源 | 判定口径 | 是否受 39.9 封顶 |
|---|---|---|---|
| **短期 S** | 结构化量化数据（`biz.asset_derivatives` / `biz.asset_unlock_pressure` / `onchain_transfer_log`） | **可复现性**：存在 + 有采集时间戳 + 新鲜度达标 | **否**（独立口径） |
| **中期 M** | 文本论点（catalyst / 解锁日程 / 上所） | URL 引用可核验 | 是 |
| **长期 L** | 文本论点（估值 / 治理 / 审计 / GitHub） | URL 引用可核验 | 是 |

**关键约束（防骗不回退）**：
- 39.9 封顶逻辑**只作用于文本论点驱动的档位**（M/L）。S 档改走「量化数据可复现」口径，**必须有等价的独立护栏**，否则就是给 91.3 翻车开后门。S 档护栏 = ① 每项输入必须来自结构化表、带 `fetched_at`；② 输出字段命名禁止出现「看涨/看跌概率」，只输出**资金面状态 + 数据完整度**。
- 命名改口：S 档叫「**短期数据完整度 / 资金面状态**」，不叫「短期确定性」。CVD/OI/费率算的是当下资金面，不是预测能力，沿用「确定性」会让用户误读为胜率。

### 2.2 期限标签：零 LLM 改动

现有 `_iter_thesis_points`（`db_stats.py:4273-4290`）已返回每个点的 `kind`（`thesis` / `risk` / `valuation` / `supply` / `sentiment` / `catalyst`）。据此建一张显式映射表即可：

```python
# 新增（db_stats.py，紧随 _DETERMINISM_TIERS 之后）
_HORIZON_BY_KIND = {
    "sentiment": "s",   # 社交热度 / 拥挤度 / KOL 情绪
    "supply":    "s",   # 筹码集中度 / 鲸鱼抛压（近端）
    "catalyst":  "m",   # 催化剂日程 / 上所 / 路线图
    "risk":      "m",   # 风险点多落在事件窗口
    "valuation": "l",   # 代币经济学 / 基本面锚
    "thesis":    "m",   # 汇总论点，默认中档
}
```

material 侧同理，复用已有 `_MATERIAL_IMPACT`（`db_stats.py:1971-1984`）的 dimension，再加一层期限：

| material key | dimension（已有） | 期限（新增） | 缺失性质 |
|---|---|---|---|
| `onchain_holder_data` | supply | S | **可采集** |
| `social_heat` | sentiment | S | **可采集** |
| `token_unlock_data` | supply | M | 可采集（低频） |
| `exchange_listing` / `roadmap` | catalyst | M | 可采集 |
| `lp_liquidity_info` / `bug_bounty` | risks | M/L | 可采集（低频） |
| `audit_report` / `dao_governance` / `github_repo` | risks/catalyst | L | **资产固有缺失** |
| `tokenomics` / `third_party_rating` / `whitepaper_docs` | valuation | L | 部分固有 |

⇒ **期限标签完全由代码层映射得出，不需要改 LLM prompt、不需要重跑结论生成**。这是相比上游方案最大的成本节省。

### 2.3 三档输入定义（每档独立计算，不共用字段）

**短期档 S（T+0 ~ 14d）** — 5 项量化输入，逐项 present 判定：

| # | 输入 | 数据源 | present 条件 |
|---|---|---|---|
| 1 | CVD 24h | `biz.asset_derivatives.cvd_ratio_24h` | 非 NULL |
| 2 | OI 变化 24h | `biz.asset_derivatives.oi_change_24h_pct` | 非 NULL |
| 3 | 资金费率 | `biz.asset_derivatives.funding_rate_pct` | 非 NULL |
| 4 | 抛压评分 | `compute_unlock_pressure()` | 非 NULL |
| 5 | 近端解锁状态 | `biz.asset_unlock_event` | 有无 <14d 事件（「无」也算 present，表示已判定） |

```
短期档分 = 100 × ( 完整度×0.5 + 新鲜度×0.3 + 方向一致×0.2 )
  · 完整度   = present 项数 / 5
  · 新鲜度   = derivatives.fetched_at ≤24h ? 1.0 : (≤168h ? 0.5 : 0.0)
  · 方向一致 = 复用 _consistency_dim()（db_stats.py:4368-4399），但仅在此档使用
```

**中期档 M（2 ~ 12 周）** — 文本论点中 `kind ∈ {catalyst, risk, thesis}` 的部分，走三维加权 `coverage 0.50 / freshness 0.20 / sample 0.30`；另消费催化剂日程与解锁事件表。
> 注：出于 §1.2 同一理由，M/L 档**刻意不含 `consistency`**——`_consistency_dim()` 只读 24h 衍生品，对 2–12 周窗口无语义。该维度仅在短期档 S 使用。

**长期档 L（季度 ~ 年）** — 先过**存在性硬门槛**（见 2.4），过了再走文本引用三维加权 `coverage 0.55 / freshness 0.15 / sample 0.30`（同样不含 `consistency`）。

### 2.4 长期档 = 存在性硬门槛（而非加权打分）

```python
def _long_term_existence(structured: dict, missing: list) -> dict:
    """三项存在性 → 0/1。任一为 0 即长期档不可评估。
    存在性本身就是事实，不需要加权，也不需要特判。"""
    checks = {
        "audit":    _present(missing, "audit_report"),      # 第三方审计报告
        "github":   _present(missing, "github_repo"),       # 公开代码库
        "governance": _present(missing, "dao_governance"),  # 治理机制
    }
    return {"checks": checks, "passed": sum(checks.values()),
            "evaluable": all(checks.values())}
```

- 三项全 1 → 长期档才进入加权计算。
- 任一为 0 → 长期档 = `not_evaluable`，且**不被 S/M 档分数拉升**（结构上就不可能，因为不参与合成）。
- PONS：三项全 0 → 长期档 `not_evaluable`，notes 输出「审计/公开代码库/治理机制三项存在性均为 0，属资产固有缺失，永久不可达」。

这样「Launchpool 长期不可评估」是**公式的自然结果**，不需要上游 §9 那样额外写特判禁令。

### 2.5 入场闸门：结构性条件，非绝对分数

上游的 `≥60 / ≥50` 是无来源的经验值。修订为结构条件 + 显式标注未校准：

| 档位 | 闸门（全部为结构条件） | 标注 |
|---|---|---|
| S | 完整度 = 5/5 **且** derivatives ≤24h **且** 无 <14d 解锁压力 **且** 方向非明确反向（CVD 转负且 OI 放大、巨鲸净抛） | `uncalibrated` |
| M | 催化剂进入可验证窗口（解锁前 N 天 / 上所已 confirm）**且** 中期 coverage > 0 **且** 命中率引用已注明口径 | `uncalibrated` |
| L | `_long_term_existence().evaluable == True` | — |

综合结论合成规则（沿用上游 §2.2，此处仅确认）：
- 仅 S 开 → 「可短线，事件/动量驱动，**禁长期持有叙事**」
- S+M 开、L 关 → 「短线 + 事件仓位」
- L 开 → 才可谈「持有」
- 任一档不适评估但其余档高 → 必须明写「X 期限不可评估，仅 Y 期限可行动」，**不得用高档掩盖低档**

每档 gate 对象都带 `calibration: "uncalibrated"`，前端渲染「经验阈值·未校准」。

### 2.6 missing 二分（大部分已存在，只需补两件事）

现状：`_compute_missing_materials_inner`（`db_stats.py:2260-2333`）**已经**输出 `impact_dimension` / `impact_desc` / `determinism_gain`。上游 §3 说这是新增，实际是**已有能力**，要补的只有：

1. **加期限维**：`horizon`（S/M/L）+ `missing_nature`（`collectable` / `intrinsic`）。
   固有缺失判定用 §2.2 表中 `L` 档的 audit / dao_governance / github_repo 三项（Launchpool 类无公开代码库、无第三方审计、无治理）。
2. **增益改为按档**：现有 `determinism_gain` 是单一数（如 onchain_holder_data=8），改为 `{"s": 8, "m": 0, "l": 0}`，前端才能显示「补链上持仓 → 短期 +8」。

## 5. P4 前向跟踪表（校准基建）

这是唯一能校准三档阈值的数据源。**不建它，阈值永远是经验值。**

```sql
CREATE TABLE IF NOT EXISTS biz.thesis_forward_track (
    track_id        SERIAL PRIMARY KEY,
    thesis_id       INTEGER,              -- biz.research_thesis.thesis_id（0=降级结论）
    asset_id        INTEGER NOT NULL,
    as_of           DATE NOT NULL,        -- 结论生成日
    tier_s_score    NUMERIC(5,1),
    tier_m_score    NUMERIC(5,1),
    tier_l_evaluable BOOLEAN,
    gate_s_open     BOOLEAN,
    gate_m_open     BOOLEAN,
    price_at        NUMERIC,              -- as_of 收盘价
    ret_t7_pct      NUMERIC,              -- 前向收益（回填）
    ret_t30_pct     NUMERIC,
    ret_t90_pct     NUMERIC,
    filled_at       TIMESTAMPTZ,
    CONSTRAINT uq_thesis_forward UNIQUE (asset_id, as_of)
);
CREATE INDEX IF NOT EXISTS idx_thesis_forward_due
    ON biz.thesis_forward_track (as_of) WHERE filled_at IS NULL;
```

- 写入时机：P2 结论生成时同步 upsert 一行（`filled_at` 为空）。
- 回填时机：日级调度，`as_of + 7/30/90` 到期时从 `biz.asset_market_daily` 取价回填。
- 使用：积累 ≥3 个月后，按 `gate_s_open` 分组比较 `ret_t30_pct`，验证短期闸门是否有区分度；M 档需 ≥6 个月、L 档需 ≥1 年。

## 6. 验收标准（可满足版，替代上游 §8）

1. **三档字段非空**：任意资产 `analysis_json.determinism_3tier` 含 `s`/`m`/`l` 三对象，各有 `score`（L 档可为 `null`）、`tier`、`gate`、`evidence_basis`、`calibration`。
2. **期限标签覆盖率 100%**：`_iter_thesis_points` 返回的每个点都能映射到 S/M/L 之一；探针注入未知 `kind` 时断言失败（不静默落到默认档）。
3. **短期档不被 39.9 压平**：构造 fixture「5 项量化输入全 present + derivatives ≤24h」，断言 S 档 score ≥ 70；同一 fixture 下 M/L 档若 coverage=0 仍为 39.9。**（口径分离断言，取代上游互斥的验收 #3）**

7. **结论文本新鲜**：P2 后首次访问 `research_thesis.updated_at` 刷新，且 `analysis_json` 含三档。
8. **板块竞品正确**（P3）：`matched_by` 含 `category=launchpad`；返回项不含 Aave/1inch。
9. **防伪断言**：源码级断言 S 档不消费 `_compute_evidence_stats()`（防止后续改动把文本口径又混回量化档）。

## 7. 边界与风险

- ⚠️ **长期档「不可达」是物理事实，不是待办。** 任何工单不得把「让 Launchpool 类长期变高确定性」列为目标。§2.4 的存在性门槛就是把这个事实**结构化**，而非「修掉」。
- ⚠️ **S 档口径分离是本方案最大的风险点。** 它给短期档开了一条绕过 39.9 的通道，必须有 §6 第 3/5/9 三条断言同时钉死，否则等于把 `96fe711` 的防骗成果重新打开。若这三条断言无法同时通过，**应放弃 S 档独立结论**（退回上游「仅综合分 + 三档标注」备选），而不是放宽口径。
- ⚠️ **阈值全部未校准。** §2.5 的结构条件已尽量去分数化，但「解锁前 N 天」「>14d」等仍为经验值。前端必须显式标注，禁止宣称「回测钉死」。
- ⚠️ **P2 校准引用有范围。** 仅 `signal_type_calibration` 表内且 `state ∈ {calibrated_ok, decayed}` 的类型可引用；`exempt_not_backtestable` 与 `missing` 一律不引用（沿用 `95d6bfc` 设计）。引用文案必须写全口径：「signal_type 层命中率 X%（n=Y，未按 tier 校准）」。
- ⚠️ **P3 板块重分类是数据写入**，属 B 组操作，需授权后执行（本方案不代执行）。

## 8. 需要拍板的两处

1. **S 档口径分离是否接受？**（`量化数据可复现` 口径 + 三条防伪断言）
   - 接受 → 短期档能输出可用结论，方案目标达成；
   - 不接受 → 三档全被 39.9 压平，短期档同样 unusable，上游方案核心目标落空。
   - 推荐接受，但**必须**以 §6 第 3/5/9 条为前置条件。

2. **P4 前向跟踪表是否本期做？**
   - 本期做 → 阈值有校准路径，但需约 3 个月才有可用样本；
   - 本期不做 → 阈值长期挂 `uncalibrated`，可接受但要写进 AGENTS.md 留档。
   - 推荐「本期只建表 + 写入，回填任务随日级调度接入」，成本低且不阻塞 P0-P2。
