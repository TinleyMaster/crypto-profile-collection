# 当前项目逻辑与流程总览（2026-07-29）

## 1. 这个项目现在到底在做什么

这个项目正在重构一套“加密货币投研资料采集与沉淀系统”。

目标不是再维护旧的 `coin_basic` 大宽表，而是改成分层体系：

1. 先把各来源 API 原始数据分开采集
2. 再把来源数据整理成来源层表
3. 再把来源层映射成统一的 `core` 实体层
4. 再把文档入口、文档资产、消费层表从 `core` 往下刷新

当前已经开始跑通的来源只有 **CoinMarketCap（CMC）**。

---

## 2. 现在的底层分层结构

### A. `raw` 层

作用：保存原始 API 响应，便于回放和审计。

核心表：

- `raw.api_response`

含义：

- 每次调用 CMC 接口，原始 JSON 都先落这里
- 后面来源层表都可以追溯到这条原始响应

### B. `src_*` 来源层

作用：把每个数据源拆开存，不混写。

当前已在跑的 CMC 来源表：

- `src_cmc.cmc_asset_map`
- `src_cmc.cmc_asset_info`

含义：

- `cmc_asset_map`：币种清单、symbol、name、slug、platform、token_address
- `cmc_asset_info`：description、logo、urls、category_hint、date_launched

### C. `core` 统一实体层

作用：把来源数据映射为统一资产实体。

当前已在跑：

- `core.asset`
- `core.asset_source_map`

含义：

- `core.asset`：统一资产主实体
- `core.asset_source_map`：记录某个 `asset_id` 对应哪个来源主键

当前第一版策略很克制：

- 只做 **CMC 单源 bootstrap**
- 暂时不做 CMC / CoinGecko / DefiLlama 的跨源智能匹配
- 先把单源主干建起来

### D. `biz` 业务层

作用：给后续文档抓取、知识库同步、消费查询使用。

当前已在跑：

- `biz.doc_source_entry`
- `biz.doc_asset`

含义：

- `doc_source_entry`：文档入口 URL 层，不是文件本体
- `doc_asset`：实际文档文件层，直链 PDF、白皮书、审计报告等最终都会落这里

---

## 3. 当前已经跑通的主链路

现在已经跑通的链路是：

```text
CMC_MAP
  -> raw.api_response
  -> src_cmc.cmc_asset_map

CMC_INFO
  -> raw.api_response
  -> src_cmc.cmc_asset_info

src_cmc.cmc_asset_map + src_cmc.cmc_asset_info
  -> core.asset
  -> core.asset_source_map

src_cmc.cmc_asset_info + core.asset_source_map
  -> biz.doc_source_entry

biz.doc_source_entry
  -> biz.doc_asset   （当前只处理第一版：直链 PDF）
```

## 4. 每条脚本现在负责什么

### 4.1 `ingest_cmc_map.py`

路径：

- `05_代码与脚本/scripts/bin/ingest_cmc_map.py`

作用：

- 调 CMC `/v1/cryptocurrency/map`
- 写 `sys.ingest_run`
- 写 `raw.api_response`
- 写 `src_cmc.cmc_asset_map`

这条链已经真实写库成功。

### 4.2 `ingest_cmc_info.py`

路径：

- `05_代码与脚本/scripts/bin/ingest_cmc_info.py`

作用：

- 调 CMC `/v2/cryptocurrency/info`
- 支持手工传 `--ids`
- 也支持 `--from-map-missing` 自动找还没补 info 的币
- 写 `sys.ingest_run`
- 写 `raw.api_response`
- 写 `src_cmc.cmc_asset_info`

这条链已经真实写库成功。

### 4.3 `backfill_cmc_info.py`

路径：

- `05_代码与脚本/scripts/bin/backfill_cmc_info.py`

作用：

- 分批调用 `ingest_cmc_info.py`
- 用来批量回填 `cmc_asset_info`

### 4.4 `refresh_core_assets_from_cmc.py`

路径：

- `05_代码与脚本/scripts/bin/refresh_core_assets_from_cmc.py`

作用：

- 从 `src_cmc.cmc_asset_map + cmc_asset_info` 中取数据
- 生成或更新 `core.asset`
- 写入 `core.asset_source_map`

说明：

- 当前只做 CMC 单源 bootstrap
- `asset_type` 只是第一版启发式分类

### 4.5 `backfill_core_assets_from_cmc.py`

路径：

- `05_代码与脚本/scripts/bin/backfill_core_assets_from_cmc.py`

作用：

- 分批调用 `refresh_core_assets_from_cmc.py`
- 避免单个超大事务卡住数据库

### 4.6 `refresh_doc_source_entries_from_cmc.py`

路径：

- `05_代码与脚本/scripts/bin/refresh_doc_source_entries_from_cmc.py`

作用：

- 从 `src_cmc.cmc_asset_info.urls`
- 结合 `core.asset_source_map`
- 生成 `biz.doc_source_entry`

当前提取的入口类型主要有：

- `official_website`
- `docs`
- `github`
- `medium`
- `other`

### 4.7 `discover_doc_assets_from_entries.py`

路径：

- `05_代码与脚本/scripts/bin/discover_doc_assets_from_entries.py`

作用：

- 从 `biz.doc_source_entry` 里读取入口
- 先做第一版“直链 PDF 发现”
- 如果入口明显是 PDF，或者探测后判定为 PDF
- 就写进 `biz.doc_asset`

说明：

- 当前还不是完整网页分析器
- 只处理“比较确定的直链文档”
- 普通官网页、GitHub 仓库页还没有进入第二版深度发现逻辑

### 4.8 `backfill_doc_assets_from_entries.py`

路径：

- `05_代码与脚本/scripts/bin/backfill_doc_assets_from_entries.py`

作用：

- 分批调用 `discover_doc_assets_from_entries.py`
- 用小批次慢慢扩充 `biz.doc_asset`

## 7. 你现在可以怎么理解这个项目

如果只用一句话讲：

> 现在这个项目正在把“从 CMC 抓币种资料，再找到官网/白皮书/文档，再把文档变成可沉淀资产”这件事，拆成一层一层可维护的系统。

如果再具体一点，可以理解为 5 个连续阶段：

### 阶段 1：先把来源数据收进来

- `ingest_cmc_map.py`
- `ingest_cmc_info.py`

### 阶段 2：把来源数据变成统一资产

- `refresh_core_assets_from_cmc.py`

### 阶段 3：把资料入口整理出来

- `refresh_doc_source_entries_from_cmc.py`

### 阶段 4：先识别出最容易拿下的文档

- `discover_doc_assets_from_entries.py`

### 阶段 5：后面再做真正下载、解析、同步

- 这部分还没正式写完
