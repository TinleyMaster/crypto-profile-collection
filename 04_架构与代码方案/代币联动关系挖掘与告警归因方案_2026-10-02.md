# 代币联动关系挖掘与告警归因方案_2026-10-02

> 目标：找出「一个代币起飞后，另一个代币大概率随后也起飞」的联动关系，并把经
> 回测验证的关系接进盘面扫描告警，给每条高置信告警打「异动归因 + 同稳定组
> 可能联动」标签。
>
> 本文档 = 方案运行逻辑（一~四）+ 数据结论（五）+ **重新审计**（六~七）。

---

## 一、方案目标

| # | 目标 | 落地形态 |
|---|---|---|
| 1 | 全市场找出「先起飞→后跟涨」的联动对 | workbench 研究脚本（离线报告 + JSON） |
| 2 | 先按已知关系（赛道/公链/产业链/公司）归组，再量化组内相关度 | `token_relation_graph.py` |
| 3 | 回测验证哪些组「真抱团」（稳定 + 有跟涨边缘） | `backtest_group_linkage.py` |
| 4 | 把稳定组接进扫描告警，打「异动归因 + 可能联动」标签 | `catalyst_attribution.py` + `scan_daemon.py` |
| 5 | 稳定组名单每周自动刷新 | `refresh_stable_groups.py` + daemon 周任务 |

## 二、整体架构与运行逻辑

### 2.1 分层架构

```
┌─ 研究层（workbench，离线）──────────────────────────────────────────┐
│ scan_lead_lag.py     全市场 lead-lag 互相关扫描 + 事件研究验证        │
│ dive_lead_lag_pair.py 指定币对深挖（复验 + 事件研究 + 催化剂归因）     │
│ token_relation_graph.py 关系图谱：赛道/公链/产业链/公司 → 组内相关度    │
│ backtest_group_linkage.py 以分组为基础的组内联动回测（稳健性+跟涨）     │
└──────────────────────────────┬─────────────────────────────────────┘
                               │ 稳定组名单（每周刷新）
┌─ 生产层（scripts/bin，常驻）────────────────────────────────────────┐
│ refresh_stable_groups.py ──▶ biz.stable_linkage_group 表（fix_085）   │
│        ▲ 周任务（scan_daemon TASK_DEFS，604800s）                    │
│ catalyst_attribution.py  告警时：自身/同赛道催化剂 → 归因标签         │
│        │                  + 读稳定组表 → 同稳定组「可能联动」候选      │
│        ▼                                                             │
│ scan_daemon._send_alerts → _render_alert_email（邮件卡片追加归因行）   │
│        └─ detail jsonb 快照 attribution_snapshot（可回放）            │
└──────────────────────────────────────────────────────────────────────┘
```

### 2.2 端到端运行逻辑

**研究链路（一次性/可重跑）**

1. `scan_lead_lag.py`：对宇宙币对算「A(t) 与 B(t+k)」相关，找最优滞后 k*；收益一律
   扣 BTC 超额（ret − ret_btc，与 `scan_signal_outcome.excess` 同口径）。分三档：
   小时级（asset_klines 1h，60 天）、日频（asset_market_daily，约 4 个月）、
   赛道轮动（等权赛道指数）。
2. `dive_lead_lag_pair.py`：对 top 日频对做四层验证——全谱复验 → 事件研究（起飞日
   → 跟随币后续超额）→ 首尾分段稳健性 → **催化剂归因**（区分「同一叙事同时打两币
   的伪领先」vs「真传导」）。
3. `token_relation_graph.py`：四个关系维度（赛道 `biz.asset_sector`、公链
   `core.asset_contract.chain`、产业链叙事 `sector_narrative_asset`、生态/公司
   CMC "* Ecosystem"）把币归组；对 top N 币算日超额同步相关矩阵，组内均值 vs
   全市场基线（tightness）。
4. `backtest_group_linkage.py`：对每个组做 ① 组相关稳健性（首/后半段是否都超基线）
   ② 组内起飞事件回测（组内某币日超额≥5% 起飞 → 同组其它币 +1d/+2d/+3d 跟涨概率
   vs 基线、平均超额、提升度）。

**生产链路（常驻）**

5. `scan_daemon._send_alerts`：对每条待发告警调用 `catalyst_attribution.attribution_for`：
   - 自身催化剂（48h）+ 同赛道兄弟币催化剂（24h，排除 BTC/ETH）→ 标签
     `independent / sector_narrative / pure_move / unlinked`；
   - 若该币命中稳定组（读 `biz.stable_linkage_group`，空/缺表回退内置默认）→
     列出同组可比兄弟币（排除 BTC/ETH + 稳定币，按市值体量相近排序）作为
     「可能联动」候选。
6. `_render_alert_email`：卡片「共振：…」行下追加归因行，如：
   `归因：纯异动 ｜ 同稳定组产业链Layer 2，可能联动：STRK、IMX、SOON`
7. 发信成功 → `detail` jsonb 落 `attribution_snapshot`（与 `resonance_snapshot`
   并列），历史邮件可字节级回放。
8. `refresh_stable_groups`（daemon 周任务，604800s）：子进程跑
   `backtest_group_linkage.py` → 提取 `stability.stable=true` 的组 → 单事务
   全量替换 `biz.stable_linkage_group`。

## 三、关键口径（全链路一致）

| 口径 | 定义 | 落点 |
|---|---|---|
| 超额收益 | `ret − btc_ret`（同步，非回归 beta） | 研究层与 `scan_signal_outcome.excess` 一致 |
| 起飞事件 | 日超额 ≥ 5%（可配 `--event-thresh`）；1h 级 24h 涨 ≥ 15% | 事件研究 |
| 跟涨概率 | `P(同组币平均超额 > 0)`；提升 lift = 事件概率 / 基线概率 | 回测 |
| 稳定组 | 组内相关在首/后半段**都**超全市场基线 | 回测 → 周任务 → DB 表 |
| 联动候选 | 命中稳定组的同组非稳定币，排除 BTC/ETH，按市值体量相近排序取前 4 | 告警归因 |

## 四、数据结论（2026-10-02 实测，311 币 × 41 天日频 / 150 币 × 60 天 1h）

1. **小时级 lead-lag 弱**：扣 BTC 后滞后相关最高 ~0.29；同步相关强
   （DOGE-SHIB 0.68、PAXG-XAUT 1.00）——币们「同时涨」而非「先后涨」。
2. **日频 top 对不稳健**：BCH→ONDO (+2d corr 0.477) 首/后半段相关 −0.04/0.13，
   全靠 2-3 个离群日；催化剂归因证实为**两个独立强利好撞车**
   （09-22 BCH ← 芝商所 CME BCH 期货；09-24 ONDO ← Ondo×贝莱德智能组合）。
3. **真抱团的稳定组**（两段样本均超基线）：
   - 产业链叙事 7 个：Layer 2 / DePIN / Layer 1 / NFTs / Metaverse /
     Liquid Staking / Yield Farming；
   - 公链 4 个：tron / bsc / pulsechain / sui；赛道仅 depin。
4. **组内起飞回测**：最佳组 +1d 跟涨概率提升 1.1~1.3x、平均超额 0.2~2.2%，
   **当日共动已 70~88%** → 联动真实但主要体现在同步，「次日跟涨」边缘很薄。
5. **总体判断**：方案的可靠价值是「**伪领先识别 + 稳定组归因**」（避免把利好驱动
   的独立行情当联动信号），而不是「预测跟涨获利」。

## 五、重新审计

### 5.1 方法学问题（中高优先级）

| # | 问题 | 证据/影响 | 建议 |
|---|---|---|---|
| A1 | **样本窗口太短** | 日频仅 41 天（首/后半段各 20 天，20 个点估相关，置信区间极宽）；1h 仅 60 天 | 回填更久历史（`phase_scan_klines --backfill-days 90`）+ 日频随积累复算 |
| A2 | **多重比较未校正** | 全市场 22350 币对 × 48 滞后，`|corr|≥0.15` 阈值未做 FDR/Bonferroni；纯噪声下必有若干「过关对」 | 报告加 p 值/FDR 校正；top 对必须过事件研究+稳健性双门 |
| A3 | **事件研究小样本** | BCH→ONDO n=4 时「跟涨 100% vs 基线 39%」看似强，剔除 2 个大阳日后不稳 | 样本 <20 只披露不判读；累积后重跑 |
| A4 | **基线污染** | dive 脚本基线只剔事件起点、未剔重叠窗口；回测脚本基线只剔本成员事件日、未剔其它成员事件日 | 基线改为「无任何事件重叠的日」 |
| A5 | **未扣交易成本** | 研究层超额未扣费；`scan_signal_outcome` 已扣 0.1% 双边费 → 1-2% 边缘扣费后更薄 | 结论层统一标注「未扣费」，与结算口径对齐后再下判断 |
| A6 | 简单收益未 winsorize | 极端日（±20%+）主导相关 | 相关计算前 1%/99% winsorize |

### 5.2 数据质量问题（中优先级）

| # | 问题 | 证据/影响 | 建议 |
|---|---|---|---|
| B1 | **LST/合成 USD 锚定对仍在** | JITOSOL-MSOL、UZDT-USD.F 等恒 ~1.0，抬升组内相关 | 排除 stablecoin 后仍需按「锚定类」单列或单独分组 |
| B2 | **生态/公司维度无数据** | CMC 生态分类成员几乎未摄入（仅 Arc 12 / Long 2）、CG coin_detail 全空 → 方案只覆盖 3/4 维度 | 建 issuer/company 映射表（Circle/Tether/Binance/Ondo…）+ 从 CMC 生态分类补数 |
| B3 | `sector_narrative_asset` 曾停更 25 天 | 归因/图谱读最新快照，停更则名单失真 | 读取前校验 `MAX(as_of_date)` 新鲜度，超窗告警 |
| B4 | core.asset 符号重复（1,866 个） | asset_id 映射可能张冠李戴 | 已用 market_cap_rank 定序缓解；保持该约定并在新查询复用 |

### 5.3 生产链路问题（中高优先级）

| # | 问题 | 证据/影响 | 建议 |
|---|---|---|---|
| C1 | **告警路径查询数偏多** | 每条告警 `attribution_for` 约 8-10 个小查询（自身/同赛道催化剂、叙事、链、联动 peers、验证组），同步串行执行；远程库实测慢（12 万行 150s 量级）→ 批量告警发送延迟可能被拉长 | ① 加查询耗时埋点/日志；② 验证组名单按进程缓存（小时级 TTL）；③ 必要时并行或超时降级 |
| C2 | 归因失败静默降级 | `_render_attribution` 异常返回空串、`attribution_for` 异常打印一行——无告警 | 连续失败达到阈值时上报（复用 scan_heartbeat） |
| C3 | 周任务失败无通知 | `refresh_stable_groups` 子进程失败只留日志，7 天后重试；期间用上次名单 | 失败时发一条维护告警（SMTP） |
| C4 | **生产迁移未应用** | fix_085 本机已应用；生产库需手动 `apply_migration.py fix_085`，否则归因走内置兜底（功能不缺失但名单不刷新） | 部署清单化 |
| C5 | 内置默认与 DB 表可漂移 | 代码注释已声明；首次刷新前两者一致（实测 12 条全等） | 保持「DB 优先 + 兜底」语义，刷新任务稳定后考虑移除兜底 |

### 5.4 口径一致性问题（低-中优先级）

| # | 问题 | 影响 | 建议 |
|---|---|---|---|
| D1 | 研究层日频（market_daily）与 1h（asset_klines）双源 | 跨粒度结论可比性有限 | 报告标注数据源；关键结论两粒度都验证 |
| D2 | 「起飞」阈值（5%/15%）为经验值 | 阈值敏感性未知 | 加阈值敏感性扫描（3%/5%/8%） |
| D3 | 联动候选「按市值相近」是启发式 | 未验证「体量相近兄弟币确实更联动」 | 用历史相关验证该启发式；或用组内相关 top-k 替换 |

### 5.5 价值评估（诚实）

- **成立的部分**：伪领先识别（催化剂归因成功拆穿 BCH→ONDO 式假信号）；稳定组
  名单（两段样本验证）；告警上下文增强（独立利好/板块叙事/纯异动 + 可能联动）。
- **不成立/未兑现的部分**：「预测同组随后跟涨」——回测显示边缘薄（lift 1.1-1.3x、
  超额 <2%），且主要同步已反映。方案不应被当作跟涨信号源，而应作为
  「归因上下文 + 板块轮动观察」。
- **成本**：告警邮件每卡片 +1 行归因；发送路径 +8-10 查询（见 C1）；周任务
  每轮 2-3 分钟子进程。

## 六、运行与运维

```bash
# 研究层（离线）
python workbench/scan_lead_lag.py                 # 全市场 lead-lag 报告
python workbench/dive_lead_lag_pair.py            # BCH→ONDO 深挖（可换币对）
python workbench/token_relation_graph.py          # 关系图谱 + 组内相关度
python workbench/backtest_group_linkage.py        # 组内联动回测

# 生产层
python scripts/apply_migration.py fix_085_stable_linkage_group.sql   # 建表（一次性）
python scripts/bin/refresh_stable_groups.py --dry-run                # 预览稳定组
python scripts/bin/refresh_stable_groups.py                          # 手动刷新
# 重启 scan_daemon：周任务自动刷新；告警邮件自动带归因行

# 验证
python scripts/bin/catalyst_attribution.py --selftest
python scripts/bin/catalyst_attribution.py --check OPUSDT   # 看归因 + 联动候选
```

依赖与风险提示：
- 所有脚本依赖生产库（`.env` 的 `DATABASE_URL`）；远程库取数慢是已知约束
  （研究脚本已做紧凑列 + 限窗优化，全量跑仍需数分钟）。
- 归因是**上下文而非闸门**：模块缺失/异常只去掉标注，不阻断告警（与 db_stats
  同款降级策略），生产安全。
