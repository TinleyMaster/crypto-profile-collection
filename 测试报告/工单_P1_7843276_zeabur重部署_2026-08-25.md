# 工单 · P1 · 7843276 行情分区可见性 · psycopg3 INTERVAL 写法修复

> 优先级：P1·高
> 问题类型：psycopg3 下 `INTERVAL '%s days'` 参数化写法不生效，导致 `days` 参数被忽略
> 影响面：所有资产研究页的行情表现分区、相关性矩阵、持仓快照、衍生品缓存等
> 现状：BTC 仅 3 天（实际应 91 天）、相关性 common_days 极低
> 目标：BTC ≥ 90 天、correlation ≥ 30 天、所有带 days 参数的查询行为正确

---

## 一、根因（最终确认）

### 错误假设 → 真实根因

| 轮次 | 假设 | 结论 |
|---|---|---|
| 第一轮 | 线上未部署最新代码（Docker 缓存） | ❌ 容器内 db_stats.py 有 16 处 cmc_historical 引用，代码是新的 |
| 第二轮 | gunicorn worker 加载旧代码 | ❌ 直接 Python 命令行调用也只返回 3 天 |
| 第三轮 | `INTERVAL '%s days'` 在 psycopg3 中不工作 | ✅ **确认！** |

### 实证

在容器内直接对比：

```python
# 硬编码 SQL → 97 行（正确）
cur.execute("SELECT COUNT(*) FROM biz.asset_market_daily WHERE asset_id = 2 AND market_date >= CURRENT_DATE - INTERVAL '90 days'")
# → 97

# 参数化 SQL → 5 行（错误，只查到最近 2-3 天）
cur.execute("SELECT COUNT(*) FROM biz.asset_market_daily WHERE asset_id = %s AND market_date >= CURRENT_DATE - INTERVAL '%s days'", (2, 90))
# → 5
```

**原因**：psycopg3 中 `INTERVAL '%s days'` 的 `%s` 会被替换成带引号的字符串（如 `'90'`），
导致 SQL 变成 `INTERVAL ''90'' days'`，PostgreSQL 无法正确解析，实际退化为 0 天或极短间隔。

### 受影响的 5 处查询

|---|---|---|

## 二、修复方案

### 正确写法

```python
# 错误（psycopg3 不工作）
AND market_date >= CURRENT_DATE - INTERVAL '%s days'

# 正确（数字乘以 INTERVAL '1 day'）
AND market_date >= CURRENT_DATE - %s * INTERVAL '1 day'
```
