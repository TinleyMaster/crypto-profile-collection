# 盘面异动扫描系统设计方案

> 版本：v0.1（草案，供多方 AI 评审讨论）
> 日期：2026-09-16
> 目标：批量扫描加密代币盘面异动，识别高确定性机会，输出可执行观察清单。

---

## 1. 背景与目标

现有系统已具备：CMB/CMC 行情日线、衍生品资金面快照（funding/OI/CVD 24h 聚合）、催化剂、KOL、解锁、链上监控、恐惧贪婪指数、板块资金流等数据与采集脚本，且已有 `auto_trade_signal.py` 交易执行链路和 `backtest_opportunities.py` 回测框架。

本方案在其之上新增一套**盘面异动扫描系统**，定位为"研究辅助"，输出盘面观察清单与信号，不直接自动下单。

**核心设计原则：**

1. 低成本粗筛优先：全市场先跑价量粗筛，命中者才拉 OI/CVD 做深度校验，控制算力与 API 消耗。
2. 双池并行：主异动扫描池 + 蓄势埋伏观察池，互补漏检。
3. 回测先行：8 个深度校验场景必须经历史回测标定后，才作为信号可信度依据。
4. 数据自积累：OI/CVD/清算等依赖时间序列的指标，从现在开始持续采样入库。

## 3. 数据层设计（本方案的数据前提）

### 3.1 数据源与免费可用性

| 数据 | 数据源 | 免费？ | 说明 |
|---|---|---|---|
| 分钟级 K 线（5m/15m/1h 全市场） | Binance `GET /fapi/v1/klines`（或 `api/v3/klines`） | ✅ | 实时拉取；现有 `signal_market_data.py` 已在使用 |
| OI 历史序列 | Binance `GET /futures/data/openInterestHist` | ✅ | 免费无 key，周期 5m~1d；**每请求≤500 条、仅保留最近 30 天**，必须自建历史表持续采样 |
| OI 实时快照 | Binance `GET /fapi/v1/openInterest` | ✅ | 单点值，无历史 |
| CVD 日内 | Binance aggTrades 计算 or 各交易所 CVD 接口 | ✅ | 需自建计算/采样；现有 `asset_derivatives` 仅 24h 聚合 |
| 资金费率 | 现有 `asset_derivatives` / `ingest_btc_funding.py` | ✅ | 已有 |
| 清算事件流（实时） | Binance WebSocket `!forceOrder@arr` | ✅ | 全市场广播，免费无需鉴权 |
| 清算历史 | Binance 官方 | ❌ | **无免费历史 REST 接口**，只能自建采集积累；回测阶段用代理指标（费率极值+价格尖刺）替代 |
| 市场环境 | 现有 fear_greed / market_daily / sector_flow_daily | ✅ | 已有 |

### 3.2 需要新建的表

**① OI/CVD 采样历史表 `biz.oi_cvd_snapshot`**（蓄势池与 OI↑↓ 判定的数据前提）

```sql
CREATE TABLE IF NOT EXISTS biz.oi_cvd_snapshot (
    symbol       TEXT           NOT NULL,
    ts           TIMESTAMPTZ    NOT NULL,          -- 采样时间
    exchange     TEXT           NOT NULL DEFAULT 'binance',
    oi_usd       NUMERIC(20,2),                    -- OI 总价值
    cvd_5m_usd   NUMERIC(20,2),                    -- 近 5m CVD
    cvd_1h_usd   NUMERIC(20,2),                    -- 近 1h CVD
    vol_5m_usd   NUMERIC(20,2),                    -- 近 5m 成交额
    PRIMARY KEY (symbol, exchange, ts)
);
CREATE INDEX IF NOT EXISTS idx_oi_cvd_snapshot_ts ON biz.oi_cvd_snapshot (ts DESC);
```

采样频率建议：每 5 分钟一次（与 5m 周期对齐），5m/1h 的 OI 变化率与 CVD 由历史序列现算，而非依赖 24h 快照。

**② 清算事件表 `biz.liquidation_events`**

```sql
CREATE TABLE IF NOT EXISTS biz.liquidation_events (
    id           BIGSERIAL PRIMARY KEY,
    event_ts     TIMESTAMPTZ    NOT NULL,
    symbol       TEXT           NOT NULL,
    side         TEXT,                             -- SELL/BUY（清算方向）
    qty          NUMERIC(24,8),
    price        NUMERIC(24,8),
    usd_value    NUMERIC(24,2),                    -- 清算名义价值
    exchange     TEXT           NOT NULL DEFAULT 'binance'
);
CREATE INDEX IF NOT EXISTS idx_liq_events_sym_ts ON biz.liquidation_events (symbol, event_ts DESC);
```

**③ 信号输出表 `biz.scan_signal`**（主池 + 蓄势池统一出口，供回测与观察清单消费）

```sql
CREATE TABLE IF NOT EXISTS biz.scan_signal (
    id           BIGSERIAL PRIMARY KEY,
    signal_ts    TIMESTAMPTZ    NOT NULL,
    symbol       TEXT           NOT NULL,
    pool         TEXT           NOT NULL,          -- 'main' / 'accumulation'
    scenario     TEXT,                             -- S1..S8 / ACC / BRK（突破转主池）
    timeframe    TEXT,                             -- 5m/15m/1h（主池多周期共振级别）
    p_dir        TEXT, price_chg_pct NUMERIC(8,2),
    vol_state    TEXT, vol_ratio      NUMERIC(8,2),
    oi_dir       TEXT, oi_chg_pct     NUMERIC(8,2),
    cvd_dir      TEXT,
    funding_rate NUMERIC(12,8),
    confidence   TEXT,                             -- high/medium/low
    context_tags TEXT[],                           -- 市场环境标签（regime）
    trigger_price NUMERIC(24,8),                   -- 建议触发价
    stop_loss_pct NUMERIC(8,2),                    -- 建议止损%（ATR 口径）
    status       TEXT NOT NULL DEFAULT 'active',   -- active/confirmed/stale/closed
    expired_at   TIMESTAMPTZ,
    created_at   TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

> 说明：粗筛候选池、蓄势池无需单独建表持久化，作为内存态/临时态处理即可；落库的是最终信号与历史采样。

### 3.3 需要新建的采集任务

| 任务 | 周期 | 说明 |
|---|---|---|

## 4. 主异动扫描池（核心管线）

### 4.1 L0 市场环境过滤（新增，必须）

扫描结果脱离市场环境没有意义。只有环境允许时才采信对应方向信号：

- **BTC 方向/主导率**：BTC 近 1h/4h 方向；BTC.D 趋势。
- **恐慌贪婪指数**（已有数据）：极端恐慌时多头信号降权，空头信号升权。
- **总市值趋势**：市场总市值处于上升段才采信多头信号。
- **板块资金流**（已有 `sector_flow_daily`）：标的所在板块净流入时加分。

输出 `context_tags`，随信号落库。

### 4.2 L1 粗筛（多周期共振，替代原"任一周期触发"）

原方案"任一周期涨跌幅超阈值即入池"误报率高。改为**升档共振**：

| 级别 | 条件 | 处理 |
|---|---|---|
| 候选 | 5m 价量异动（价格 ±3%、量 ≥2×均值） | 进入候选，不拉 OI/CVD |
| 入池 | 15m 同向异动 | 进入 L2 深度校验 |
| 高置信 | 1h 同向异动 | 进入 L2，且信号权重 ×2 |

- 量能判定用"当前周期成交额 vs 近 N 周期均值"（N 建议 20），避免用 24h 快照。
- 三周期方向**必须一致**才升级；5m 单独异动只观察。
- **资金费率不参与 L1 粗筛**：费率是 8h 结算的慢变量，与分钟级异动时间维度不匹配；且行情启动初期费率通常仍处中性区间，作为触发条件会漏掉早期行情。费率仅作为 L2 拥挤度辅助标签。

### 4.3 L2 深度校验（8 场景）

**指标定义（本方案补充口径要求）：**

- P：当前周期价格方向（与 L1 一致）。
- VOL：放量 / 缩量（当前成交额 vs 近 20 周期均值）。
- OI：本周期 OI 变化方向（由 `oi_cvd_snapshot` 序列计算，**不是 24h 快照**）。
- CVD：本周期累计成交量差方向（正 = 主动买盘强）。
- funding（资金费率）：辅助**拥挤度风险标签**，**不参与任何筛选/触发**。8h 结算一次、慢变量；正数 = 多头持仓拥挤、多头持续付息；负数 = 空头持仓拥挤、空头持续付息。仅在 L2 用于评估反转/过热风险。

**8 场景**（仅 VOL↑ 采信为交易信号；VOL↓ 一律降级为观察，不生成预警）：

| # | P | OI | CVD | VOL | 解读 | 信号 |
|---|---|---|---|---|---|---|
| S1 | ↑ | ↑ | ↑ | ↑ | 现货买盘强 + 合约新开多仓，真实多头进攻 | 多头趋势延续 |
| S2 | ↑ | ↑ | ↓ | ↑ | 现货主动卖，上涨靠合约杠杆，诱多 | 警惕回调（空头候选） |
| S3 | ↓ | ↑ | ↓ | ↑ | 现货砸盘 + 合约新开空单，真实空头 | 空头趋势延续 |
| S4 | ↓ | ↑ | ↑ | ↑ | 现货承接，下跌由合约空头砸出，诱空 | 存在反弹潜力 |
| S5 | ↑ | ↓ | ↑ | ↑ | 合约平仓 + 现货买入，获利了结 | 反弹近尾声 |
| S6 | ↑ | ↓ | ↓ | ↑ | 空头回补，非新多进场 | 修复反弹 |
| S7 | ↓ | ↓ | ↓ | ↑ | 空头止盈平仓，跌势衰竭 | 衰竭信号 |
| S8 | ↓ | ↓ | ↑ | ↑ | 现货承接 + 空头离场，抛压释放 | 见底反弹 |

**资金费率拥挤度标签（附加于 8 场景，辅助层、不参与触发）：**

| 场景 | 附加费率标签 |
|---|---|
| S1 | 费率持续大幅正 → 多头过热，警惕短期回调；费率中性/小幅正 → 健康多头行情 |
| S2 | 高正费率 → 多头极度拥挤，诱多概率进一步放大 |
| S3 | 费率持续大幅负 → 空头过热，警惕空头回补反弹；费率中性/小幅负 → 健康空头行情 |
| S4 | 高负费率 → 空头极度拥挤，诱空概率进一步放大 |
| S5 | 高正费率叠加 → 多头集中兑现，反转风险升高 |
| S6 | 负费率叠加空头平仓 → 反弹力度更强 |
| S7 | 高负费率叠加空头平仓 → 见底反弹概率提升 |
| S8 | 高负费率加持 → 抛压释放，反弹潜力更大 |

> **定位说明（为什么费率不进 L1 粗筛）：**
> 1. 费率是 **8h 结算一次**的慢变量，而价量/OI/CVD 是分钟级高频数据，时间维度不匹配，不适合做异动触发条件。
> 2. 行情刚启动时费率往往还在中性区间，等行情走一段后才变为大幅正/负；拿费率当触发条件只能抓到行情后半段，错过启动点。
> 3. 费率极端值更多是**风险预警信号**（拥挤/过热），不是异动发生信号。

**判定增强（相对原方案）：**

1. **S2/S4 叠加资金费率**：OI↑ + 极端正费率 → S2 诱多概率↑；OI↑ + 极端负费率 → S4 诱空概率↑。
2. **S2/S4 叠加实时清算**：若近期出现同方向大额清算，进一步验证杠杆挤压叙事。
3. **OI 二阶信息**：OI 是加速抬升还是减速？加"OI_chg 是否在扩张"标记。
4. **CVD 状态切换**：CVD 从负翻正（或反之）比持续同向更有效，单独标记。

**置信度分级（2026-09-16 P1 首轮回测标定后修订，替代初版）：**

> 标定依据（§8）：仅 P↑OI↑ 组合稳定正期望（24h 净 +5.24%、盈亏比 2.01）；P↓\* 空头侧全部负期望；1h 短窗口被成本吃光。**多头优先、空头默认降级。**

- 高：P↑OI↑（S1/S2 基础）方向 + 市场环境顺风 + 多周期共振；窗口取 4h/24h（1h 置信度下调）
- 中：P↑OI↓（S5/S6 基础，24h 才转正）；S4/S8 逆势类仅作观察、不预警
- 低/降级：空头场景（S3/S4/S7/S8）默认不生成交易预警，仅当 L0 判定为空头 regime 时采信
- 待验证：CVD 维（S1/S2、S7/S8 拆分）无历史源，需 WebSocket 流式积累后补标定；样本仅 21 天，需随 OI 窗口拉长复验

## 5. 蓄势埋伏观察池（旁路）

**触发条件（全部满足）：**

1. 价格波动小：短周期（15m/1h）涨跌幅低于异动阈值（如 <1.5%）。
2. 成交量无明显放大：成交额 < 近 20 周期均值 1.5 倍。
3. **OI 连续多周期持续上行**：基于 `oi_cvd_snapshot` 历史序列，如近 12 个 1h 周期 OI 抬升占比 ≥70% 且累计变化 >5%。
4. （可选）同步跟踪资金费率，观察蓄势阶段多空是否提前拥挤——仅作观察，不作为进出池条件。

**增强判定（可选：同步抓取资金费率，观察蓄势阶段多空是否提前拥挤）：**

- 叠加 funding 区分吸筹/派发：
  - OI↑ + funding 接近 0 或小幅正 → 多空均衡吸筹，偏多头潜力；
  - OI↑ + funding 大幅负 → 空头持续建仓，存在逼空潜力；
  - OI↑ + funding 大幅正 → 多头拥挤，警惕派发。
- 蓄势时长记录：进入蓄势池的时间戳，超时（如 7 天）未突破自动出池。

**转主池触发：**

- 后续出现放量（量比 ≥3×）+ 价格突破（突破蓄势区间上/下沿），自动转入主池 L2 校验，标记 `pool='accumulation', scenario='BRK'`。

## 6. 信号合成：去重 / 冷却 / 生命周期 / 催化层加分

1. **去重与升级**：同币 5m/15m/1h 多周期触发时，保留最高级别一条，其余挂起为佐证。
2. **冷却**：同币信号触发后冷却 N 小时（建议 6h），冷却期内只记录不重复预警。
3. **生命周期**：`active → confirmed（突破触发价）→ stale（超时，如 4h）→ closed`。
4. **催化层加分（新增，替代"盲区完全排除"）**：盘面信号与以下既有数据共振时加分——
   - 催化剂事件（`biz.catalyst_impact` 正/负向）
   - KOL 信号（`kol_auto_trade_log` / KOL 监控）
   - 代币解锁压力（`unlock_watchlist`）
   - 链上大额转账监控（`onchain_transfer_log`）
   共振标记随信号落库，供人工决策。

**双层告警（2026-09-17 落地，替代每日摘要）：**

> 时序分层依据：解锁/链上转账等**领先型**信息先于盘面（可提前埋伏）；KOL/突发新闻等**滞后型**信息后于盘面（仅作确认）。因此告警分两层，盘面触发时两类信号碰撞。

| 层 | 脚本 | 机制 |
|---|---|---|
| 事件预置层（先行） | `phase_build_event_watchlist.py`（每 6h） | 未来 14 天解锁（`unlock_watchlist`）+ 近 7 天链上大额转账 ≥$10M（`onchain_transfer_log`，过滤稳定币/封装/质押噪音）→ `biz.event_watchlist` |
| 盘面触发层 | `scan_alert_monitor.py`（每 5 分钟） | 新 high 置信主池信号（P↑OI↑ 标定最优组合）或蓄势 BRK high → 共振核查（事件预置=埋伏型 / 催化剂+KOL=确认型）→ 实时邮件，同币 12h 冷却，`scan_signal.alerted_at` 去重 |

> 交付渠道：**实时邮件**（非每日摘要）；`send_scan_signal_brief.py` 已从调度移除（仅保留脚本备查）。

## 7. 过滤规则与系统盲区

1. **流动性过滤（量化阈值）**：24h 成交额下限（建议 ≥ 500 万美元）+ 合约存在且流动性达标（`asset_liquidity` 表）+ 价差过滤；刷量/小盘代币直接剔除。
2. **缩量场景**：无论组合如何，只标记不预警。
3. **资金费率定位**：仅做拥挤度辅助判断，**不作为筛选触发条件**，避免过滤掉行情早期启动机会。
4. **数据源口径**：CVD 明确现货 or 合约口径，跨交易所归一化（`cvd_ratio`）；避免误读。
5. **盲区声明**：
   - 消息面冲击、解锁事件、链上大额转账 → 由催化层加分项覆盖，但该层数据本身有滞后。
   - funding 结算点（00/08/16 UTC）前后 OI/CVD 噪声大，扫描结果标记该时段。
   - 清算历史无免费源：回测时 S2/S4 用代理指标验证。

## 10. 轧空行情扫描（Squeeze Scan，2026-09-21 新增）

与主池（§4）、蓄势池（§5）并列的**第三个检测池**：针对「价格快速拉升 + 空头被迫平仓」的轧空行情，
输出**行情性质判定 + 告警邮件**。定位与 §1 一致——**只做数据监控与告警，不含任何下单逻辑**。

### 10.1 三阶段

| 阶段 | 内容 | 落点 |
|---|---|---|
| ① 轮询扫描 | 短窗口涨幅 + 放量初筛 → OI/爆仓/CVD 三重轧空确认 → 入跟踪队列 | `task_scan_squeeze` 阶段 1 |
| ② 跟踪 | 用实时价刷新峰值、计算回撤幅度、判到期 | 同上，阶段 2 |
| ③ 胜负判定 | 冲高回撤后，用**回撤窗口**的 OI/CVD/多空比/爆仓结构判定多空胜负 | 同上，阶段 3 |

> **核心口径（务必区分两个窗口）**：拉升阶段的 CVD 上涨是**空头平仓**（空头买回）造成的，
> **不能**用来判断多空胜负；胜负**只看冲高之后回撤窗口**的指标。这是本模块与 §4 主池最本质的差别。

| 常量 | 值 | 含义 |
|---|---|---|

| `SURGE_VOL_RATIO_MIN` | 1.5 | 拉升初筛放量倍数（vs 前 20 根均量） |
| `OI_SHORT_COVER_PCT` | -0.3% | 轧空确认：OI 变化上限（价升 OI 降 = 空头回补特征） |
| `SQZ_SHORT_LIQ_RATIO_MIN` | 0.00008 | 轧空确认：空头爆仓额 / 24h 成交额 下限 |
| `SQZ_CVD_RATIO_MIN` | 0.02 | 轧空确认：cvd_ratio 下限 |
| `RETRACE_THR` | 2.0% | 触发判定的回撤幅度 |

| `TRACK_QUEUE_MAX` | 12 | 队列容量上限 |
| `SQUEEZE_COOLDOWN_H` | 6 | 同币判定后冷却（小时） |

| `CVD_BUY_MILD` / `CVD_SELL_MILD` / `CVD_SELL_STRONG` | +0.02 / -0.08 / -0.15 | 回撤窗口 cvd_ratio 分档 |

> 全部阈值**跨币可比**：一律用「窗口金额 / 24h 成交额」的比例口径，不用绝对美元额（绝对额在小盘/大盘间不可比）。

### 10.6 判定规则（`evaluate_battle`，互斥分支）

```text
big_long_liq = long_liq_ratio >= LONG_LIQ_RATIO_THR        # 回撤窗口出现大额多头爆仓
d_oi_pct     = 回撤窗口 OI 变化率（%，基于 peak 时刻基准桶）
cvd_ratio    = 回撤窗口净主动成交 / 窗口成交额 ∈ [-1, 1]

if   cvd_ratio <= CVD_SELL_STRONG and big_long_liq:   -> short_win    # 多头踩踏
elif d_oi_pct  <= OI_EXIT_PCT and not big_long_liq:   -> profit_take  # 多头止盈离场/趋势衰竭
elif d_oi_pct  >  OI_EXIT_PCT and cvd_ratio >= CVD_BUY_MILD and not big_long_liq:
                                                       -> long_win     # 新多承接
       （若 top_ratio_chg < 0，即大户持仓多空比下降 → 降级为 churn，疑似换手）
else:                                                 -> churn        # 震荡消化
```

四个结论与邮件标签：

| conclusion | 标签 | 含义 |
|---|---|---|
| `long_win` | 多头胜（新多承接） | 持仓维持 + 主动买占优，新多头接住了抛压 |
| `short_win` | 空头胜（多头踩踏） | 主动卖强 + 大额多头爆仓 |
| `profit_take` | 多头止盈离场（趋势衰竭） | OI 快速下降（多头离场）且无多头爆仓 |
| `churn` | 多空平局（震荡消化） | 其余（含大户多空比下降的疑似换手） |

方向判据来自**大户持仓多空比变化 `top_ratio_chg`** 与**主动买卖比 `taker_ratio`**；
**OI 只承担「持仓是维持还是离场」这一件事**，不承担方向。

### 10.7 对原始伪代码的 6 处修正（本模块的设计依据）

| # | 原伪代码问题 | 修正 |
|---|---|---|
| 1 | 引用了未定义的 `CVD_peak`，且混用拉升期与回撤期的 CVD | 显式区分「拉升阶段 CVD 增量」与「回撤窗口 CVD 增量」，**胜负只用后者** |
| 2 | 用累计 CVD 的绝对量作比例基准，跨时段不可比 | 归一化为 `cvd_ratio = 窗口净主动成交 / 窗口成交额 ∈ [-1,1]`，跨币跨时段可比 |
| 3 | 分支 1/2 的 OI 条件完全相同，无法区分方向 | 引入大户持仓多空比 / 主动买卖比作**方向判据**，OI 仅承担「维持还是离场」 |
| 4 | `MIN_LIQ` 等绝对金额阈值无定义且跨币不可比 | 一律改为「窗口爆仓额 / 24h 成交额」比例 |
| 5 | 分支 3（OI 快速下降）语义被写成「平局」 | 更正为 `profit_take`（多头止盈离场 / 趋势衰竭），与 `churn` 分离 |
| 6 | 判定只在首次回撤 2% 时触发一次，缺少观察期约束 | 增加「高点后最小观察时长」`MIN_OBSERVE_MIN` 与「跟踪期上限」`TRACK_EXPIRE_MIN` |

### 10.8 落库与告警

- **无任何下单逻辑**（与 §9 执行层完全解耦）

## 13. 风险与局限

- 免费数据源有 30 天 OI 窗口限制，长历史依赖自积累，回测样本前期受限。
- 清算历史缺失，S2/S4 回测只能近似验证。
- 免费 API 限频（Binance `/futures/data/*` weight 限制），全市场高频采样需设计节流与分批。
- 所有信号均为概率性参考，需配合严格风控（仓位/止损/冷却）使用。
