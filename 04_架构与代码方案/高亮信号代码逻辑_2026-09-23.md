## 1. 定位

「⚡高亮信号」是大盘分析链路（`macro_market.py`）产出的**看多机会精选池**，与「🛡️高危信号」（看空/风险）互为对称。它**不是**独立的数据采集或扫描系统，而是对既有机会池的**二次精选 + AI 复核**：

| 环节 | 输入 | 输出 |
|---|---|---|
| 机会池生产 | 各数据源生成段 | `opportunities`（全量，已分 HIGH/MED/LOW） |
| 高亮精选 | `opportunities` | `highlight_signals`（≤ `highlight_max_total` 条） |
| AI 复核 | `highlight_signals` | 挂 `ai_analysis_v2` 后重排的信号 |
| 消费 | 上一步结果 | Web 首页「⚡高亮信号」区 / 日报邮件「🎯 AI 精选高亮信号」 |

高亮信号与高危信号**共用同一套底层打分与分级**，只在「方向过滤 + 评分轴 + 配额表」三处分叉。

## 2. 端到端数据流

```

   ▼

   │  apply_horizon_to_opportunities()            macro_market.py:3166
```

| `mvrv_deep_over` / `mvrv_over_watch` | MVRV 高估（**只进高危**） | short | long / 90 / 60（估值类） |

### 3.2 `_push_opportunity()`：入池闸门

[macro_market.py:2877-2921](file:///e:/瞎搞乱搞/web3/加密货币研究报告/05_代码与脚本/workbench/macro_market.py#L2877-L2921)

1. **去重**：以 `(signal_type, target.strip())` 为键，在 `opportunities + excluded` 中查找，命中即 `return`（不覆盖、不累加）。
2. **打分**：`raw = opp["conviction_score"]`（缺省 45）→ `_finalize_conviction()` 得到最终 `conviction_score`，并把三个解释字段写回 opp：
   - `conviction_strength` = 未调制前的 `raw_strength`
   - `regime_mult`、`resonance_bonus`
3. **分档过滤**：
   - `HIGH`：`score ≥ conviction_high_min`（默认 **70**）
   - `MED`：`score ≥ conviction_med_min`（默认 **55**）
   - 低覆盖放宽：若 `conviction_breakdown.coverage_weight < min_available_weight`（默认 **0.5**），MED 阈值降为 `conviction_med_min_low_coverage`（默认 **50**），并写 `coverage_note`
   - `LOW` → 进 `excluded`，**不进机会池**（因此不可能成为高亮）
4. 写入 `conviction_tier`。

> **注意**：`_push_opportunity` 只追加 `conviction_*` 系列字段，**不清空**其它字段——因此生成段写入的 `event_strength`、`related_dims`、`involved_symbols` 会原样透传到后续阶段。

## 4. 阶段二：确定度（conviction）打分

### 4.1 六轴加权 —— `_conviction_breakdown()`

[macro_market.py:2968-3021](file:///e:/瞎搞乱搞/web3/加密货币研究报告/05_代码与脚本/workbench/macro_market.py#L2968-L3021)

| 轴 | 子分公式（clamp 到 0-100） | 权重键（默认值） | 数据缺失时 |
|---|---|---|---|
| `mvrv` | `100 - mvrv_pct`（低估=高分） | `conviction_weight_mvrv`（0.23） | 50（中性） |
| `funding` | `50 - funding*10000`（正=过热） | `conviction_weight_funding`（0.14） | 50 |
| `netflow` | `50 + netflow/1e9*20`（净流出=做多） | `conviction_weight_netflow`（0.14） | 50 |
| `stable` | `50 + stablecoin_flow/1e10*30` | `conviction_weight_stable`（0.09） | 50 |
| `roi` | `50 - roi_1yr*30`（超跌=做多） | `conviction_weight_roi`（0.14） | 50 |
| `catalyst` | 净情绪分（0-100） | `conviction_weight_catalyst`（0.08） | 50 |

- `raw_strength = clamp(round(Σ 子分×权重), 0, 100)`，**不含周期调制**。
- `coverage_weight = Σ(有数据轴的权重)`，供低覆盖放宽判定（§3.2）。
- 返回 `{axes: {轴: {score, weight, contribution, available}}, raw_strength, coverage_weight}`，供前端解释。

权重在 `market_rules.yaml` 的 `opportunity_rules` 段覆盖（[market_rules.yaml:79-84](file:///e:/瞎搞乱搞/web3/加密货币研究报告/05_代码与脚本/workbench/market_rules.yaml#L79-L84)）。

> **注意**：六轴中**任一轴缺失都按中性 50 计分**，因此「单轴事件型信号」（whale/kol/chain/narrative 等）会被大量中性轴稀释、塌缩到 55-60 区间（线上曾出现 4 条 MED 全部 = 60、内部零区分度）。这就是 §4.2 事件强度主轴存在的原因。

### 4.2 事件强度主轴（A1）—— `_event_strength_score()`

[macro_market.py:3028-3049](file:///e:/瞎搞乱搞/web3/加密货币研究报告/05_代码与脚本/workbench/macro_market.py#L3028-L3049)

把信号自带的「真实事件量」连续映射为 0-100 主轴：

| kind | 映射 | 锚点 |
|---|---|---|
| `usd` | `50 + 12*log10(max(\|v\|,1)/1e6)`，clamp[40,90] | $1M→50 / $100M→74 / $1B→86 |
| `flow_pct` | `50 + min(40, \|v\|*4)`，clamp[40,90] | 链 / TVL 7d 变化率 |
| `mcap_pct` | `50 + min(40, \|v\|*3)`，clamp[40,90] | 叙事板块 7d 市值变化率 |

`value` 为 `None` 或非法 → 50（中性，不惩罚）。

**融合方式**：五类软信号生成段把六轴 raw 与事件强度按 6:4 混合后回写：

```
conviction = round(0.6 * conviction + 0.4 * es)
opp["event_strength"] = es      # 透传给前端「事件强度 N · 共振×M」
```

落点：`whale_flow`（`usd_total`）、`narrative`（`mcap_change_7d_pct`）、`chain_inflow`（`flow_pct`）、`kol_onchain`（单源封顶）、`etf_flow`（BTC 与非 BTC 共 3 处，金额单位百万→×1e6 后走 `usd`）。

> **注意**：`kol_onchain` 在 `n_confirm < 2`（单源）时 `es = min(es, 45)`，压制单源情报的确定度，使其不靠事件强度硬冲高亮。

### 4.3 周期调制 + 共振加分 —— `_finalize_conviction()`

[macro_market.py:3052-3071](file:///e:/瞎搞乱搞/web3/加密货币研究报告/05_代码与脚本/workbench/macro_market.py#L3052-L3071)

```
score = clamp(round(raw_strength × regime_mult + resonance_bonus), 0, 100)
resonance_bonus = min(cap, max(0, n_confirm - 1) × step)
```

- `regime_mult` 由周期相位决定：底部类 `early_bottom 1.15 / bottom 1.12 / late_bottom 1.10`，中部 `1.00`，顶部类 `early_top 0.85 / top 0.82 / late_top 0.80`，`unknown 1.00`（`_CYCLE_REGIME_MULT`）。
- 共振：`conviction_resonance_step`（默认 **6**）、`conviction_resonance_cap`（默认 **18**），即每多 1 个独立确认源 +6 分，最多 +18。
- 写入 `raw_strength / regime_mult / resonance_bonus` 供前端解释。

## 5. 阶段三：周期标注 / 线性衰减 / 估值过滤

[macro_market.py:3099-3183](file:///e:/瞎搞乱搞/web3/加密货币研究报告/05_代码与脚本/workbench/macro_market.py#L3099-L3183)

`apply_horizon_to_opportunities(opportunities, t, btc_mvrv_pct)` 对全池逐条：

1. `_annotate_horizon()`：写入 `horizon / expire_days / is_valuation / signal_date / days_old`，并算
   `decayed_score = _decay_strength(conviction_score, days_old, expire_days)`
   `_decay_strength`：`days_old ≥ expire_days → 0`；否则 `strength × (1 - days_old/expire_days)` 线性衰减。
2. `_apply_valuation_filter()`（**仅非估值类信号**且 `btc_mvrv_pct` 可用）：
   - BTC MVRV 百分位 ≥ `valuation_filter_high_pct`（默认 **85**）且方向 `long` → `decayed_score ×= valuation_filter_mult`（默认 **0.5**）
   - ≤ `valuation_filter_low_pct`（默认 **15**）且方向 `short` → 同样打折
   - 命中时写 `valuation_filter_note`（如「估值过热，多头信号衰减 ×0.5」）
   - 估值类信号（`is_valuation=True`，即 4 个 MVRV 信号）**跳过**该过滤

排序阶段优先使用 `decayed_score`（无则回落 `conviction_score`），使「旧信号」自然下沉。

## 6. 阶段四：高亮精选 —— `select_highlight_signals()`

[macro_market.py:4272-4410](file:///e:/瞎搞乱搞/web3/加密货币研究报告/05_代码与脚本/workbench/macro_market.py#L4272-L4410)

签名：`select_highlight_signals(opportunities, max_total=10, min_resonance=2)`
主链路调用参数：`max_total = highlight_max_total`（默认 **10**）、`min_resonance = 1 if ai_v2_enabled else 2`（[macro_market.py:5772-5780](file:///e:/瞎搞乱搞/web3/加密货币研究报告/05_代码与脚本/workbench/macro_market.py#L5772-L5780)）。

### 步骤 1：方向过滤（一票否决）

```
long_opps = [o for o in opportunities
             if o.direction in ("long", None, "", "bullish")
             and o.signal_type not in ("mvrv_deep_over", "mvrv_over_watch")]
```

即**空头信号绝不进高亮区**，且两个「高估」估值信号被显式剔除。`long_opps` 为空直接返回 `[]`。

### 步骤 2：排序取候选池

排序键（降序，五元组）：

```
(is_high, is_new_today, len(related_dims), decayed_score or conviction_score)
```

`is_high = conviction_tier == "HIGH"`。候选池取前 `max_total × 10` 条。

### 步骤 3：同标的合并（target 小写为键）

同一 `target` 的多条信号合并为**一张卡片**：

- 主卡 = 首次出现（即排序最靠前）的那条，浅拷贝；
- `all_signals` 累积所有子信号；`related_dims` 去重合并；
- `conviction_score` / `conviction_tier` 取**子信号中的最高值**；
- 计算 `resonance_count = len(set(signal_type))`，写入 `signal_types`。

### 步骤 4：净方向裁决

若同一 target 的子信号里 `long` / `short` **数量不等且总数 ≥ 2**，则主卡 `direction` 改为**多数方向**，并把 `action_hint` 覆写为「多信号方向不一致，按净方向以多数为准…」。

> 目的：防止「一条错配的反向子信号」把整体方向顶成相反（曾出现 ZEC 三连派发被一条 outflow 顶成「多」）。

### 步骤 5：共振筛选

`_is_symbol_target(tgt)` = 匹配 `^[A-Z0-9]{2,10}$`（纯币种 symbol）。

- **币种级 target**：要求 `resonance_count ≥ min_resonance`，否则整张卡片剔除；
- **宏观 / 聚合类 target**（含中文等，如「恐贪指数极度恐惧」）：**不受共振限制**。

V2 模式下 `min_resonance=1`（即不筛），把质量判断权交给 AI（§7）。

### 步骤 6：类型配额 + 截断

按主卡 `signal_type` 计配额（**配额计的是合并后的卡片数，不是信号数**）：

| signal_type | 配额 | | signal_type | 配额 |
|---|---|---|---|---|
| `mvrv_deep_under` | 3 | | `funding` | 2 |
| `mvrv_under_watch` | 2 | | `token_unlock` | 2 |
| `catalyst` | 3 | | `kol_onchain` | 2 |
| `whale_flow` | 3 | | `fng_extreme` | 2 |
| `github_activity` | 2 | | `leverage_extreme` | 2 |
| `stablecoin_inflow` | 2 | | `etf_flow` | 2 |
| `price_surge` | 3 | | `price_volume_surge` | 3 |
| `volume_surge` | 2 | | `sector_inflow` | 2 |
| `narrative` | 2 | | `chain_inflow` | 2 |
| `__default__` | 2 | | | |

按主卡分数降序逐条取，超配额跳过，累计到 `max_total` 停止。

> **注意**：配额表内嵌在函数里（非 yaml），改配额需改代码；`narrative` / `chain_inflow` 有独立配额，避免全部落入 `__default__` 互相挤占。

### 高危信号对照

`select_risk_signals()`（[macro_market.py:4416-4543](file:///e:/瞎搞乱搞/web3/加密货币研究报告/05_代码与脚本/workbench/macro_market.py#L4416-L4543)）与之对称，差异仅三处：

## 7. 阶段五：AI 增强 V2 —— `ai_enrich_signals_v2()`

[ai_signal_analyzer.py:3290-3391](file:///e:/瞎搞乱搞/web3/加密货币研究报告/05_代码与脚本/workbench/ai_signal_analyzer.py#L3290-L3391)

开关：`ai_highlight_enabled`（默认 **"1"**）与 `ai_v2_enabled`（默认 **"1"**）。V2 关闭时回落旧函数 `ai_enrich_highlight_signals` / `ai_enrich_risk_signals`。调用参数：`direction="long"`、`max_ai_review = ai_highlight_max`（默认 **15**；风险侧 `ai_risk_max` 默认 **12**）。

### 步骤 1：分类过滤——谁该送 AI

`should_send_to_ai()`（[ai_signal_analyzer.py:2179-2227](file:///e:/瞎搞乱搞/web3/加密货币研究报告/05_代码与脚本/workbench/ai_signal_analyzer.py#L2179-L2227)），规则来自 yaml `opportunity_rules`（[market_rules.yaml:124-151](file:///e:/瞎搞乱搞/web3/加密货币研究报告/05_代码与脚本/workbench/market_rules.yaml#L124-L151)）：

- **事件驱动类**（`ai_event_driven_signals`，13 种：`token_unlock / funding / catalyst / kol_onchain / whale_flow / etf_flow / leverage_extreme / fng_extreme / stablecoin_inflow / price_volume_surge / price_surge / price_crash / volume_surge`）→ **单条出现即送**；
- **未知类型** → 保守也送；
- **慢变量类**（`ai_slow_variable_signals`，7 种：4 个 MVRV + `github_activity` + `sector_inflow/outflow`）→ 需 `≥ ai_slow_min_resonance`（默认 **2**）种共振才送；
- 附加门槛：`has_valid_asset = bool(asset_id) or 匹配 ^[A-Z0-9]{2,10}$`，**聚合/宏观类信号直接跳过全量画像**（避免 LLM 因数据不足误判降级，保持原排名）。

成本控制：按 `conviction_score` 降序取前 `max_ai_review` 条。

### 步骤 2：逐币全量画像分析 —— `analyze_asset_v2()`

## 10. 已知边界与待决

1. **单轴信号仍受六轴稀释**：§4.2 只对 5 类软信号做了「事件强度 6:4 融合」，其余单轴信号（如 `btc_left_accum`、`cm_adoption_divergence`）仍走纯六轴加权，存在被中性轴稀释、在 MED 内无区分度的可能。
2. **配额与阈值硬编码在函数内**：`select_highlight_signals` 的 `quotas`、`V2 开关默认值` 未外置 yaml，调参需改代码。
3. **AI 降级信号仍占展示位**：`_ai_downgraded` 只抑制徽章，不移除卡片，也不降低其在 `mixed` 排序中的位置权重以外的排序优先级（仍可能与「AI 认可」并列展示）。
4. **`min_resonance=1` 时共振筛选实质失效**：V2 模式下币种级信号不再要求多源共振，质量完全依赖 AI 复核；若 AI 不可用（`ai_enabled=false` 或 LLM 失败静默），精选将退化为「纯分数 + 配额」，无共振把关。
5. **AI 增强为静默失败**：主链路用 `try/except: pass` 包裹，AI 异常时高亮列表保持规则精选结果且无任何 `ai_analysis_v2` → 邮件「AI 精选」模块整块不渲染。
