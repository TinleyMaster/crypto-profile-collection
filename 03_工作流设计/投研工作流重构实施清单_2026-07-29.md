# 投研工作流重构实施清单（2026-07-29）

## 1. 重构目标

这次不迁移旧数据，直接从新库结构出发，重建整套 n8n 工作流。

唯一总原则：

```text
raw -> src -> core -> biz
```

也就是：

1. 先把 API 原始响应写进 `raw`
2. 再解析进各自来源表 `src_*`
3. 再做统一实体与映射 `core`
4. 最后才生成业务消费表 `biz`

---

## 2. 新工作流体系总览

建议把工作流拆成 4 层：

### A. 采集层

- 负责请求外部 API
- 只做轻量清洗
- 原始响应先落 `raw.api_response`

### B. 来源解析层

- 把 `raw.api_response` 解析写入 `src_cmc / src_cg / src_llama`
- 每个来源独立维护，不跨源互写

### C. 统一映射层

- 把来源数据映射成 `core.asset / core.protocol / core.chain`
- 生成 `asset_source_map / protocol_source_map`
- 弱匹配进 `mapping_candidate`

### D. 业务消费层

- 刷新 `biz.coin_basic`
- 刷新 `biz.research_target`
- 刷新 `biz.doc_source_entry`
- 运行文档抓取、时序汇总、投研输出

---

## 4. 第一阶段必须先做的 8 条工作流

如果你想最快跑出新系统，我建议先只做下面 8 条。

### 4.1 `WF_CMC_MAP_INGEST`

目标：

- 从 CMC `/v1/cryptocurrency/map` 拉全量目录
- 先写 `sys.ingest_run`
- 再写 `raw.api_response`
- 再解析写 `src_cmc.cmc_asset_map`

节点顺序建议：

```text
Schedule Trigger / Execute Workflow
-> PG_INSERT_INGEST_RUN
-> HTTP_CMC_MAP
-> CODE_BUILD_RAW_RECORD
-> PG_INSERT_RAW_API_RESPONSE
-> CODE_PARSE_CMC_MAP
-> PG_UPSERT_CMC_ASSET_MAP
-> PG_FINISH_INGEST_RUN
```

说明：

- 这条工作流不写 `biz.coin_basic`
- 这条工作流只负责 CMC 目录事实层

### 4.2 `WF_CMC_INFO_BATCH`

目标：

- 对 `src_cmc.cmc_asset_map` 已有资产批量补详情
- 写入 `src_cmc.cmc_asset_info`

推荐输入：

- 从 `src_cmc.cmc_asset_map` 按批次取 `cmc_id`
- 每批 `50-100` 个

节点顺序建议：

```text
Execute Workflow
-> PG_SELECT_CMC_IDS_TO_ENRICH
-> LOOP_OVER_ITEMS
-> HTTP_CMC_INFO
-> PG_INSERT_RAW_API_RESPONSE
-> CODE_PARSE_CMC_INFO
-> PG_UPSERT_CMC_ASSET_INFO
-> PG_FINISH_INGEST_RUN
```

### 4.3 `WF_CMC_QUOTES_LATEST`

目标：

- 拉取最新行情
- 写 `src_cmc.cmc_asset_quote_snapshot`

注意：

- 这条只进 `src_cmc`
- 不直接写 `biz.asset_market_daily`

### 4.4 `WF_CG_COIN_DETAIL_BATCH`

目标：

- 以 `coingecko_id` 或待补 ID 列表为输入
- 把 CoinGecko 的详情写入 `src_cg.cg_coin` 和 `src_cg.cg_coin_detail`

说明：

- 这条是 CMC 信息缺口的重要补充
- 官网、docs、github 可以拿来补 `biz.coin_basic`

### 4.5 `WF_LLAMA_PROTOCOLS_INGEST`

目标：

- 拉 `DefiLlama /protocols`
- 写 `src_llama.llama_protocol`

关键原则：

- 只当它是协议表，不当资产表
- 先别急着回填 `coin_basic`

### 4.6 `WF_CORE_MAPPING_REFRESH`

目标：

- 从 `src_cmc / src_cg / src_llama` 生成统一实体与映射

这条工作流要做 4 件事：

1. 先创建或更新 `core.asset`
2. 建立 `core.asset_source_map`
3. 创建或更新 `core.protocol`
4. 建立 `core.protocol_source_map`

匹配策略建议只做强匹配：

- 合约地址完全一致
- 官网主域名一致
- 明确的官方 source id 对应

弱匹配不要直写，写入：

- `core.mapping_candidate`

### 4.7 `WF_BIZ_COIN_BASIC_REFRESH`

目标：

- 根据 `core.asset + source_map + src_*` 刷新 `biz.coin_basic`

这条工作流只做一件事：

- 生成“消费层读表”

字段优先级建议：

- `official_website`: `CMC > CoinGecko > manual`
- `docs_url`: `CMC > CoinGecko > manual`
- `github_url`: `CMC > CoinGecko > manual`
- `logo_url`: `CMC > CoinGecko`

### 4.8 `WF_BIZ_DOC_SOURCE_ENTRY_REFRESH`

目标：

- 从 `biz.coin_basic` 里抽取入口链接
- 写进 `biz.doc_source_entry`

作用：

- 把文档入口从消费层字段，变成专门的入口队列表

## 5. 第二阶段再做的 5 条工作流

### 5.1 `WF_DOC_DISCOVERY_QUEUE_BUILD`

目标：

- 从 `biz.doc_source_entry` 读取待处理入口
- 生成文档抓取任务队列

输入来源：

- `official_website`
- `docs`
- `github`

### 5.2 `WF_DOC_FETCH_AND_PARSE`

目标：

- 发现 PDF / docs / whitepaper / audit
- 下载文件或提取正文
- 计算 `content_hash`
- 写入 `biz.doc_asset`

### 5.3 `WF_DOC_UPLOAD_AND_REGISTER`

目标：

- 上传到 Google Drive / ima
- 回写 `drive_file_url / ima_doc_url / sync_status`

### 5.4 `WF_BIZ_ASSET_MARKET_DAILY_REFRESH`

目标：

- 从 `src_cmc.cmc_asset_quote_snapshot`
- 和 `src_cg.cg_market_snapshot`
- 汇总成 `biz.asset_market_daily`

### 5.5 `WF_BIZ_PROTOCOL_METRIC_DAILY_REFRESH`

目标：

- 从 `src_llama.llama_protocol_metric_daily`
- 汇总到 `biz.protocol_metric_daily`

## 8. 你现在最应该先重写哪一条

我建议第一条就重写：

## `WF_CMC_MAP_INGEST`

因为它是新系统最底层的资产入口，决定了后面所有东西的起点。

旧逻辑是：

```text
CMC_MAP -> coin_basic
```

新逻辑必须改成：

```text
CMC_MAP -> sys.ingest_run -> raw.api_response -> src_cmc.cmc_asset_map
```

这一步改对了，后面整个系统的方向才不会再跑偏。

---

## 9. 和旧工作流最大的差异

### 旧系统思路

- 一抓到就想写 `coin_basic`
- 不同来源直接揉成一张表
- 文档入口直接绑在主表字段上

### 新系统思路

- 原始响应先归档
- 来源事实各写各的
- 统一映射层单独处理
- `coin_basic` 只是输出，不是入口

---

## 10. 我给你的落地建议

不要一口气把 10 条都搭完。

最稳的节奏是：

1. 先搭 `WF_CMC_MAP_INGEST`
2. 验证 `raw.api_response` 和 `src_cmc.cmc_asset_map`
3. 再搭 `WF_CMC_INFO_BATCH`
4. 再搭 `WF_CORE_MAPPING_REFRESH`
5. 最后才接文档流

这样你每一层都能独立验收，不会再出现“流程跑通了，但底层结构已经歪了”的情况。
